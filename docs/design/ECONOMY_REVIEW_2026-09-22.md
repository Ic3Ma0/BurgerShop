# 0–15 级经济审计与修订依据

日期：2026-09-22。基线：本地 HEAD `ac82671` 加当前工作区；080/081 的首单、小店扩建代码已在工作区，082 人物改动也在进行。本报告核对源码并做静态计算，没有重新运行 Unity，没有修改游戏规则。

## 结论

**金币循环结构成立，但尚未满足“整体经济已平衡”的验收条件。** 目前没有租金、原料费和持续工资，正常售卖不会因为现金耗尽而亏损停产；这不等于不会出现无效消费、长期等待或后期购买失去意义。

确认需要修复的是：额外汽车窗口的付费升级未影响服务冷却；投资建议主要按低价排序；离线奖励参考价受少量未付尾款影响。需要测量后调参的是：各阶段实际入账速度、扩建与雇工完整投入、升级边际价值、自动化前后的节奏。Lv.16 以后指数价格和线性收入奖励还存在长期撞墙风险，不应声称无限等级已经平衡。

执行规格：[BS-SPEC-083](../specs/BS-SPEC-083-经济一致性修复与节奏标定.md)。这次产品交付不是游戏实现或经济验收通过。

## 1. 公式应该怎样用于本游戏

依据 [GAME_CORE](../GAME_CORE.md) 与 [节奏不变量](../../.cursor/rules/burgershop-pacing-invariants.mdc)。其历史功能表和旧价格不再代表当前状态。

```text
R = 正常经营实际入账金币 / 有效经营分钟
    排除离线领取、测试加钱、补偿和窗口开始前积存现金的集中领取
    不扣除本次正在评估的建设/升级支出；如有经常性经营成本才扣除

T_next（秒）= 60 × max(0, 当前报价 - 钱包可用余额) / R

C_open = 从当前状态到业务能真正营业的所有必要剩余投入
T_open（估算）= 60 × max(0, C_open - 钱包可用余额) / R

ΔR = 相同经营条件下，购买后收入率 - 购买前收入率
回本时间（分钟）= 购买成本 / ΔR，仅在 ΔR > 0 时成立
```

R 为 0 时不能显示“0 秒能买到”，应找缺货、站位、垃圾、客流或未收钱原因。钱已足够则 T=0，与收入率是否为 0 无关。

T_open 是维持原经营收入不变的对照估算。建设期间改变产能、占用员工、改变走位时，必须记录实际用时，不能把每一步的时间机械相加。地面现金不等于可立即消费的钱，必须单独记录。

核心关系是“目标可达、投资有价值、持续有下一步”，**不是所有价格都必须指数增长，也不是所有升级都必须增加金币**。员工可能减少玩家操作，容量可能减少往返，土地提供实际空间；这些价值必须可观察。不能把机器理论产量当成 R。

## 3. 当前支出与完整投入

### 购买设施与扩建

商城重复购买公式为 `ceil10(基础价 × 1.25^当前持有数)`；免费初始设施也计数。已有部分投入抵扣，实际付款取当前购买入口的报价。

| 投资 | 当前价格或完整投入 | 结论 |
| --- | ---: | --- |
| 第二台汉堡机 | 基价 200；已有一台时商城 250 | 不能继续用 200 当实际第二台报价 |
| 第二个汉堡柜台 | 基价 250；已有一个时商城 320 | 第二套完整厨房为 570；已有柜台能消化新增产量时，机器可单独买 |
| 新两人餐桌 | 基价 150；已有两桌时商城 240 | 不能把初始桌视为不计数 |
| 四人桌、方桌、垃圾桶 | 基价 200 / 150 / 50 | 仍受实际持有数与开放条件影响 |
| 主厅扩建、首次雇员 | 150+50=200 | 新档必须先扩厅才能进入 HR；旧档已拥有主厅不能重复收费 |
| 卫生间 | 300 | 可选改善，不应因“还没买”强制卡住升级 |
| 蓝盒工作台 | 首套 150 | 需要汉堡供应；Lv.5 可学习打包，Lv.6 才有汽车销售 |
| 首个汽车窗口 | 当前 Lv.6 自动开放 | `EnsureDriveThruOpen` 会恢复首个购买状态；不能再把 250 当作必付地价。额外窗口按商城计价，已有一个时为 320 |
| 可乐业务 | 利用现有合法空间：机器 200+柜台 250=450；购买可乐侧翼则另加 300，总计 750 | 这两条路径必须区分。商城允许在自有地摆放，侧翼不是所有可乐经营的硬前置 |
| 骑手区域及首套设施 | Lv.8 现有开放奖励 | 200 红盒机、150 托盘是额外设施基价，不能再算进首套必付投入 |

员工升级作用于所有已雇员工，并由后来雇入者继承。相同价不等于相同总回报，但这是团队成长的合理奖励，未测量前不按人数倍增升级费。旧评估中“携带某档完全没有收益”已过时：当前容量不增加的档位有额外移动收益；仍需检查描述与实际增益一致。

一个收益示例：主机 3→2 秒，理论增产 10 汉堡/分钟，若每件都能新增卖出 10 金币，则 ΔR=100，30 金币理论回本 18 秒。**这是忽略客流、搬运、用餐和收钱约束的上限情景，不是真实回本结论。** 初级柜台理论 100 件/分钟，单台初始机器仅 20 件/分钟，故“升级柜台”很可能不是当时有效的增收投资。

## 4. 星星不耗尽，不等于节奏合理

当前 Lv.1–15 的晋级消耗依次为：`2,4,5,6,6,7,8,9,10,11,12,14,16,17,20`。到达 Lv.15 共 127 星，进入 Lv.16 共 147 星。首单与教学里程碑、有效购买和升级提供星；普通重复订单不重复发星。

四条属性线有 160 星，加上设施等来源，静态数量足够。但玩家若只能买大量无关属性来凑星，即使数学可达，仍不满足经营核心。

当前 [InvestmentGuide](../../Assets/_Project/Scripts/UI/InvestmentGuide.cs) 保留目标后，默认用可负担程度、价格、ID 排序；没有按缺货、搬运和排队瓶颈区分实际价值。旧 076 的强制属性任务已取消，新的推荐还需补足“为什么值得买”。保留每次有效投资 +2 星，不直接用“贵就多给星”掩盖价值问题。

## 5. 关键风险分级

| 等级 | 发现 | 处理 |
| --- | --- | --- |
| 必修 | 汽车窗口升级不改变其真正服务冷却 | 接通实际收益；同一升级只扣款、发星一次 |
| 必修 | 指引以低价替代经营价值，员工升级购买入口本身也未要求已雇员工 | 推荐有效投资；无人时明确先雇人，不引导购买暂不生效的员工属性 |
| 必修 | 离线参考价包含餐桌剩余尾款 | 改用该档完整标价；不把历史投入当成离线产能下降 |
| 必须核验后调参 | 完整投入 200/450/570/750 与当前 R 是否匹配 | 分阶段测收入、购买后收益和实际攒钱时间；只改越界项 |
| 必须核验后调参 | 自动化单线 20/3 金币/秒理论上限约 400/分钟，低价投资是否瞬间失去选择意义 | 测整店和该线贡献，不能把理论上限当实际入账，也不直接削弱自动化奖励 |
| 尚不符合完整内核 | 离线收益仍未关联实际产出，且初级员工一晚仅约 1.21 次最便宜升级 | 尾款问题先修；整体公式需独立校准，不以当前防溢出上限宣布回访节奏合格 |
| 范围外长期风险 | Lv.16+ 价格指数增长，现金奖励线性增长 | 单独标记长期经济未验收；不以 0–15 修订顺手重写长线 |

离线当前公式：`floor(最便宜可用升级报价 × 8 × 员工数/3 × (1+0.03×员工两项等级之和)/2.2 × min(离线分钟,480)/480)`。最便宜报价 50 时，8 小时一名基础员工约 60、三名基础员工约 181、三名满级员工 400。若参考尾款只有 1，分别变为 1、3、8。这个结构会使部分付款后的奖励异常变小。

来源：[OfflineEarnings](../../Assets/_Project/Scripts/Economy/Rules/OfflineEarnings.cs)、[OfflineUpgradeCostSource](../../Assets/_Project/Scripts/Economy/OfflineUpgradeCostSource.cs)。没有在线产出输入，不能说已经实现 `产出×离线时长×效率`。

## 6. 价格敏感性：计算示例，不是实测

钱包为 0、收入恒定，单位为秒：

| 目标成本 | R=120/分钟 | R=240/分钟 | R=400/分钟 |
| ---: | ---: | ---: | ---: |
| 30 | 15 | 7.5 | 4.5 |
| 50 | 25 | 12.5 | 7.5 |
| 200 | 100 | 50 | 30 |
| 450 | 225 | 112.5 | 67.5 |
| 570 | 285 | 142.5 | 85.5 |
| 750 | 375 | 187.5 | 112.5 |
| 1,160 | 580 | 290 | 174 |

同一个 200 的目标，在三个收入情景下完全不同；不能仅按标价判定贵或便宜。大目标可以分段经营，但每段都必须有真实改善或明确的经营决策，不靠空洞任务让玩家忙起来。

Lv.16+ 示例：假设基础收入持续为 400/分钟，不再扩产，钱包为 0。

| 当前等级 | 下一次费用 | 含等级加成收入/分钟 | 攒够费用/秒 | 只靠本次 +2% 增收回本/分钟 |
| ---: | ---: | ---: | ---: | ---: |
| 16 | 500 | 448 | 67.0 | 62.5 |
| 20 | 875 | 480 | 109.4 | 109.4 |
| 25 | 1,759 | 520 | 203.0 | 219.9 |
| 30 | 3,538 | 560 | 379.1 | 442.3 |
| 40 | 14,313 | 640 | 1,341.8 | 1,789.1 |

每档新增收入为基础 400×2%=8/分钟，所以回本与攒钱时间不同。这证明固定产能下曲线会拉长，不证明真实玩家必然在对应等级停下。现有无限等级没有自动解决长线目标的价值问题。
