# Goal 08：本地存档

当前玩家可见规则以 [BS-SPEC-067-本地经营存档](specs/BS-SPEC-067-本地经营存档.md) 为准（schema v17：等级/星星/设施/餐桌档位/地块）。下文保留 Goal 08 阶段的历史实现与验证记录。

## 使用方式

正常游玩即可。金币、总成交数、烤台等级、员工雇佣状态和员工已送单数每两秒自动保存；应用失去焦点、切到后台、正常退出时立即保存。屏幕底部显示保存或恢复状态。

重新 Play 或关闭后重开，恢复上述经营进度，员工无需再次付费且继续工作。玩家位置、正在排队或离场的顾客、手上和烤台上的汉堡、生产计时在每次启动时重新初始化，不计算离线收入。

存档位置为 `Application.persistentDataPath/restaurant-save.json`，上一份有效快照位于同目录的 `restaurant-save.json.bak`。Editor/macOS 当前产品默认路径通常为 `~/Library/Application Support/DefaultCompany/BurgerShop/`；Android 使用应用私有目录，最终构建标识和路径约定见 Goal 09。

## 可靠性与边界

- JSON 当前使用版本 **8**（店铺等级 `shopRank` / `goalIndex` / `goalProgress`）。v7 及更早不读这些字段，按已建设施与投入推断最低档，已买权益保留。版本 1 仍可读：`workerHired==true` 视为 1 名员工。版本 2 仍可读：强化档与额外设施视为 0 / 未买。版本 3 / 4 仍可读：若有 `boostLevel` N 则迁移为玩家 Speed 与 Carry 都是 N；版本 3 的员工强化档视为 0。版本 5 仍可读：装箱 / 得来速视为未买。版本 6 仍可读：投入视为 0。更高版本拒绝写入。校验金币、成交数、等级和员工统计的合法范围，并校验 SHA-256 摘要以发现不完整或被意外改写的数据。摘要不是防作弊机制。
- v8 在 v7 的五处投入之外增加店铺等级 1–6 与当前阶段目标进度。钱包、投入、已购结果和等级同次保存。v1–v7 校验字节序保持。
- v7 新增 `tableInvestment` / `grillInvestment` / `counterInvestment` / `boxingInvestment` / `driveThruInvestment`，分别限制在 0–150 / 200 / 250 / 150 / 250。钱包、投入和已购结果同次保存；完成设施时立即请求下一次 LateUpdate 保存。v1–v6 校验字节序保持，旧已购权益保留，未购投入默认 0。
- v8 新增每张已建成餐桌的套装与升级投入：`table0Set` / `table1Set` / `table2Set` / `extraTableSet`（0=开局，1–3=Bistro/Diner/Patio）以及对应 `tableNInvestment` / `extraTableInvestment`（0–80）。套装非 0 时该桌投入必须为 80。未购买加桌时加桌字段必须为 0。投入满且套装仍为 0 表示待选套。v1–v7 校验路径保持；旧档桌椅为开局套。
- 台面 RAW / 在制 / BOX、PACK、部分订单及落地现金仍不持久化；未完成订单不能保存成成交，无离线收入或加工。
- 先将完整 JSON 写入同目录临时文件并刷新到磁盘，再替换主存档；正常替换保留上一份备份。不会把未完成的临时文件当成已提交进度。
- 主存档不可读但备份有效时恢复备份，随后修复主存档，并保留有效备份。
- 两份存档都不可读，或发现更高版本的存档时，保留原文件并在界面说明保存不可用，不用初始进度覆盖旧文件。遇到写入错误时显示失败并在后续保存周期重试。
- 保存发生在完整玩法事务结束后的 LateUpdate 或应用生命周期回调中；升级扣款与等级、雇佣扣款与员工状态写入同一快照。
- 恢复钱包、等级和员工不会发出售卖/消费事件，不重复扣钱、不播放购买提示音。原有 UI 在恢复之后创建，避免把余额变化误显示为本次收入。
- 强制杀进程、断电或操作系统来不及回调时，可能丢失最近约两秒尚未保存的变更；异常写入可退回上一份有效快照。卸载应用或清除应用数据会删除私有存档。

## 实现

`RestaurantSaveData` 定义版本和校验约束；`LocalSaveStore` 处理文件、校验与备份；`RestaurantPersistence` 在 bootstrap 完成业务组件绑定后恢复，再管理自动保存与暂停/退出回调；`SaveHud` 显示结果。

钱包、升级区和员工增加独立的恢复入口，恢复等级时同步制作周期与等级灯，恢复员工时按 `hiredWorkerCount`（旧档则 `workerHired` → 1 人）创建。临时测试目录通过 Editor SessionState 指定，正式 Android 构建不包含该 Editor 路径逻辑。
