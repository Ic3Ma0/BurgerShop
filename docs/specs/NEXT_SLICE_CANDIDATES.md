## BS-SPEC-011：雇人之后的店内下一目标

**玩家可见变化：** 已经花 50 金币雇到那一名员工之后，店里出现一个**仍在本店、仍是汉堡循环内**的下一个可见目标（例如：把烤台升到下一档、或完成 N 笔由员工经手的成交）。玩家不再只能站着看员工跑。目标必须是现有设施能完成的事；不新开第二间餐厅。

**范围内：**

- 仅在「已雇佣」之后出现；未雇人时保持 0.1.2 行为（若 010 已合并，则未雇人仍走 010 的首局指引）。
- 目标必须可完成、可失败边界清晰（钱不够、烤台已满级、员工正在送餐等）。
- 若目标进度需要重开后仍在，使用现有存档字段（金币、成交数、烤台等级、是否已雇、员工送单数）推导，或按正式 spec 增加兼容字段。

**范围外：**

- 不新增第二名员工、员工升级区、解雇 / 工资。
- 不新增第二种商品、座位、柜台库存、第二间店或地图扩展。
- 不把现有 10 / 30 / 50 / 60 改成「更像 Pizza Ready」的数；若目标消耗金币，必须用**当前**价目表。
- 不引入离线收益。

**经济 / 存档 / 真机：**

| 项 | 是否需要 |
| --- | --- |
| 经济数值 | 不改价；若目标是「再升一级烤台」，沿用 30/60 |
| 存档 schema | **要兼容**。默认保住旧档；若必须新字段则升版本并给默认值。可用现有字段表达的目标优先不改 schema |
| Android 真机 | 建议要：雇佣后 HUD 已较挤，新目标条不能挡摇杆；若只加文案且不改输入命中区，正式 spec 可降为 Editor + 一次竖屏安装抽查 |

**验收（草案）：**

1. **Given** 已雇一名员工、烤台 LV1、余额足够升 LV2；**When** 玩家看向店铺（无需再操作雇佣区）；**Then** 出现一个明确的下一目标（例如升到 LV2），且雇佣区仍显示已雇佣、不再扣 50。
2. **Given** 上一状态；**When** 玩家在紫色区停留 1.5 秒完成升级；**Then** 该目标标记完成（或换成正式 spec 写下的下一档，例如 LV3），金币按现有 30 扣除，产能变为 2 秒/份。
3. **Given** 已雇人的旧 0.1.2 存档；**When** 读取并存档版本升级（若有）；**Then** 金币、成交数、烤台等级、员工仍在，不重复收费；下一目标按恢复后的状态计算，而不是空白。
4. **Given** 烤台已 LV3 且员工已在自动送餐；**When** 玩家没有正式 spec 列出的后续店内目标；**Then** 不伪造「去开第二间店」，只显示已完成或等待营业，店仍是一间。
