# BS-SPEC-041 升级阶梯延长（玩家与员工的速度 / 携带）

> ⚠️ 编号请按仓库当前最大编号核对后调整（本地看到最大为 BS-SPEC-038）。

- 版本：v1.0
- 状态：草案（待用户点选）
- 对应基线：0.1.2
- 优先级与原因：**最高**。当前玩家与员工的速度 / 携带各只有 **5 级**，是全部梯子里最长的；玩家在几十单内就会见到 `Boost MAX`，"赚钱 → 升级 → 效率提高"的期待随之消失。本刀把这条循环从 5 级延长到 20 级。
- 前置依赖：无
- 用户已确认：待确认
- 产品建议或关键未定项：见下方「开发默认参数」，数值可由开发按验收标准微调。

## 目标与范围

玩家目前买满 5 级速度 / 携带后，这条升级线就结束了。本次之后，这四条线各有 **20 级**，玩家在很长的经营过程中始终有"再攒一点就能升级"的下一步。

本次交付：

1. `PlayerBoost` / `StaffBoost`：等级上限 5 → **20**；成本由固定数组改为**公式**。
2. 携带量 / 移动速度的效果曲线加入**软上限**，避免 20 级时出现荒谬数值。
3. 每级至少一处**可见变化**（见下）。
4. **修正存档校验中硬编码的上限**（本刀的关键风险点，见「边界、存档与兼容」）。
5. 相关 UI 文案去掉硬编码的 "5"。

本次不做：

- 不改任何其它价格（烤台 30/60、柜台 100/200、打包台 120/240、餐桌 80、设施解锁、纸袋线、雇工 50/100/200 全部保持）。
- **不新增离线收益、广告、内购。**
- 不改店铺等级（Rank 6）与 `ShopRanks`。
- 不新增任何系统、货币或设施。

## 玩家流程与规则

沿用现有 Boost 房间与员工升级板的交互，不新增入口：进入范围 → 长按/点击购买 → 扣金币 → 等级 +1 → 立即生效。

| 项目 | 明确规则 |
| --- | --- |
| 触发条件 | 与现状完全一致（`BoostUpgradeZone` / `StaffUpgradeBoard`），不改半径、不改计时 |
| 费用 | 由公式生成：`Cost(n) = Round10(50 × 1.18^n)`，n 从 0 起算。示例：第 1 级 50、第 5 级 100、第 10 级 270、第 15 级 610、第 20 级 1,160。**这是开发默认参数，可按验收标准微调** |
| 上限 | `MaxTier` = 20（四条线共用同一张成本表；员工与玩家成本一致，这是现状，保持） |
| 效果 | 携带：前 8 级每级 +1，之后每 2 级 +1。速度：前 6 级每级 +15%，之后每级 +8%。**不要线性外推到 20 级**——线性外推会让 20 级速度达到约 21 单位/秒，明显失真 |
| 状态变化 | 每次购买等级 +1，最多 20 次（原为 5 次） |
| 与已有功能的关系 | 与现状一致：玩家与员工各自独立升级；升级立即影响搬运与行走，不改动库存、金币、收银节流规则 |

## 界面与资源（涉及呈现时填写）

- 入口 / 位置 / 反馈时机：沿用现有，不改布局。
- 状态文案：`BoostUpgradeZone.cs:109` 的 `"Boost MAX\n5 / 5"` 必须改为**动态**（读取实际上限），否则 20 级时文案会撒谎。同理检查 `StaffUpgradeBoard` 与 `WorldLabelHud` 中所有硬编码 "5"。
- **每级可见变化（必做）**：本刀的核心风险是"只是把重复劳动拉长"。因此每级至少要有以下之一：携带等级提高时角色手上/背包的堆叠视觉档位变化、速度等级提高时移动表现变化、或升级点位的等级指示器逐级点亮。**不接受只改数值、画面完全不变的实现。**
- 界面语言：沿用现有英文。
- 资源交付：沿用现有占位视觉即可，不引入外部素材。

## 边界、存档与兼容

| **旧存档（等级 0–5）** | 必须能正常读取，进度不丢，不重复收费 |
| **新存档（等级 6–20）** | 必须能正常存档与读回。**注意：`RestaurantSaveData.cs:158,161` 把上限硬编码为 `> 5`，等级 6 以上会被判为非法存档** —— 必须改为读取 `PlayerBoost.MaxLevel` / `StaffBoost.MaxTier`，不要在两处各写一个数字 |

| 重复操作 / 多角色同时操作 | 沿用现有 `TrySpend` 保护，不新增并发规则 |
| 切后台与重新进入 | 沿用现状 |
| 存档 schema | **不升版本**：四个字段本就是 `int`，容量足够。仅修正校验上限 |

当前优先高效实现功能：按改动做必要的本地 Unity 验证，普通逻辑优先针对性测试，视觉/交互按需通过 Computer Use 操作 Unity Play。

| AC-02 | 新档 | 连续购买 20 次 | 每次只扣该级成本、等级 +1、效果立即生效；第 21 次拒绝且不扣钱 |

## 附：给开发的三句提醒

1. **存档校验是本刀唯一的地雷。** `PlayerBoost.MaxLevel` 和 `RestaurantSaveData.cs:158,161` 是两处独立的上限，必须同步。
2. **不要只把数组拉长。** 成本改用公式、效果加软上限，是这一刀的一部分，不是可选优化。
3. **"每级可见变化"是验收项，不是加分项。** 只延长梯子而不给可见反馈，等于把重复劳动拉长——那是本刀要避免的结果，不是它的目标。
