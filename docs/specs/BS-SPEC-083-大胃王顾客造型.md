# BS-SPEC-083 大胃王顾客造型

用户要求：购买更多汉堡、支付更多钱的胖人物有独立造型，和普通人一样自然出现，但不要过于频繁。按已有语义为大胃王顾客，而非雇佣员工。

## 产品规则

- 接续 030 和 082，使用已有 BigEater，不新增顾客系统。
- 专属轮廓：圆肚子、较宽的肩和脸、背带裤、暖黄色汉堡图案上衣，普通休闲短发。与普通顾客、穿围裙的员工和主厨可区分；不添加羞辱性文字或表情。
- 继续经现有入口进门、排队、逐件收餐、付款和用餐。订单气泡仍显示实际剩余份数。
- 原有低频规则不变：Lv.2 且已成交至少 5 单；符合抽取条件时 7% 大胃王、8% 通话客、85% 普通客；特殊客后至少 3 位普通客，同一队列最多 1 位特殊客。因此实际大胃王占比低于 7%，不是固定每十四人一个。饮品、车道、袋装队列不额外引入。
- 原有订单不变：10 个汉堡，逐件补货，收齐后结算 1 单。基础单价 10，共 100 金币；当前已有店铺收益加成仍按原结算处理。不额外增加大胃王倍率。

## 节奏影响

本次是既有大单事件的可见性修正；出现概率、解锁、订单、售价、产能均不变，故不改变 T(n) 计算规则，不声称测得实际攒钱耗时。不新增等待、付费或平行机制。

## 技术边界与方案审查

- 归属与复用：CharacterVisualFactory 按已有 bigEater 参数生成专属外观；复用 CharacterVisualResources 资源管理与 HumanoidVisual 动画。
- 状态归属：身份/订单归 CustomerAgent，低频间隔归 SpecialCustomerPolicy，排队归 CustomerQueue，付款归 BurgerServingZone；外观没有新的经营状态。
- 依赖方向：顾客创建调用外观，外观不访问钱包、队列或存档。原策略阈值命名集中在原策略类，保持值不变。
- 兼容与失败：不改存档、寻路占位、碰撞尺寸、根节点缩放。模型重新创建即可生效；中途补货及重复结算沿用原订单契约。
- 自动防线：检查专属轮廓、无新增碰撞、7% 条件抽取区间、普通客间隔和特殊客互斥；定向执行原大单交付测试及新造型渲染测试。执行 check-boundaries.sh。

## 验收

1. 实际 CustomerAgent.Create(BigEater) 有专属肚子、背带、汉堡图案，普通顾客没有；同屏比较可识别。
2. 未解锁/队列已有特殊客时不生成；连续极高随机数也被至少三位普通顾客隔开。
3. 订单仍为 10，可先交 4 再交 6，整单只结算一次；基础结算仍为 100。
4. 渲染预览通过测试指定身份，不能作为已观察到自然随机频率的证据；自然频率通过策略测试验证。
