## 实现与范围

- `Economy/OfflineEarnings.cs` 使用 decimal 原样实现三行公式，最后向下取整到整数金币。没有效率系数。无可购买升级时为 0；0 员工为 0。
- 当前最便宜升级按**完整标价**求最小值，不按余额缺口；枚举烤台、玩家/员工能力、可用餐桌三选一、GrowthUpgrades 与循环等级。未解锁/不活动设施不参与，已满升级不参与；商城新增设施购买不算升级。
- `RestaurantPersistence.cs` 在加载/返回前台结算，离开前记录 UTC 时间。负时长归零并重置时间戳；超过 480 分钟按 480 分钟。
- 金币、已消费时间戳、结算回执写入同一份原子替换存档，成功后才更新内存钱包。失败不发钱，后续保存先重试结算。暂停/焦点回调合并为一次离开/返回。
- `OfflineSettleHud.cs` 展示离开时长、员工人数及到账金额；零员工提示雇人。**自动到账，Continue 只关闭回执**，不会再次发钱。未关闭回执会持久化；若下次离开又产生收益，显示最新一段的回执，之前到账金额仍在钱包。
- 043 已落地且已占用 schema v15，所以本刀实际为 **v15 → v16**。v1–v15 校验和格式不改；v16 仅追加时间戳和回执字段。v14/v15 首次迁移不补发历史收入。
- `Goal01Bootstrap.cs` 仅增加离线面板接入。此次没有修改既有价格、升级曲线、042 门槛或 043 商城/摆放规则；工作区其他未提交改动属于之前任务，不是本刀 diff。
- 钱包达到 long 上限时仅入账剩余可表示空间，避免整数溢出；不额外改变正常范围公式。

## 残余风险与节奏影响

**本地存档游戏无法完全防篡改：改存档（并重算非密钥 checksum）、恢复旧备份等仍可绕过。** UTC 回拨检测和 8h 截断只能限制本次本地计算，不能证明时间真实，也不能防反复快进系统时钟。没有服务器校验，不声称“已防住”。

本刀作用于跨会话间隔时钟，强化既有雇工的价值；不新增币种/产物/升级线。在线攒钱速率 r 与升级标价 C 不变：原 T=C/r；已有余额 B、回归授予 G 后，为最便宜一项所需的剩余在线时间变为 `max(0,C-B-G)/r`（不能把最多 8×当前最低价理解为后续 8 次涨价升级都买得起）。实际 r 取决于经营/路线，未编造实测耗时。无广告首曝、无新 MAX、无强制等待。

## Continue 点击修复

原因：HudChrome.Panel 默认 raycastTarget=false，Continue 添加 Button 后未重新开启，点击被遮罩接收。仅在 Continue 的 Image 上开启 raycastTarget，不修改通用面板行为。新增 ContinueReceivesPointerClickAndDismissesWithoutPayingAgain：使用 EventSystem.RaycastAll 断言最前命中 Continue，发送指针按下/抬起/点击事件，断言面板关闭、回执关闭状态落盘、金币不再次增加。离线专项 **9/9 通过**，证据 `Logs/spec051-offline/continue-click-tests.xml`。
