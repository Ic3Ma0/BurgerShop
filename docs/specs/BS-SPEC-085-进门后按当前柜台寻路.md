# BS-SPEC-085 进门后按当前柜台寻路

- 状态：已实现，定向验证通过，实际试玩待用户复验。
- 用户问题：顾客进门后先直走、后退，然后才走向汉堡柜台；移动柜台后更明显。
- 范围：修复进店到队尾的无意义折返，保留室外生成、过门、个体步速、先进先出和原服务规则。不改变存档、空间、价格、产能或星星。

## 行为

1. 室外顾客沿既有街道穿过大门，刚过门后按当前柜台的真实队尾位置寻路。旧布局的深处入口点、预设 queueEntry 不再是必须到访的位置。
2. 路线遵循实际设施障碍，柜台移走后不再绕行其旧位置的虚拟障碍。合并路线不再把导航结果强行转为按旧柜台决定的直角绕行。
3. 移动、旋转柜台确认后，复用布局修订号刷新路线；新顾客从公共街道生成并到新槽位排队。
4. 保留排队顺序、准确到位、门口通行和自然朝向；真实障碍所必需的绕行仍然允许。

## 技术边界与方案审查

- 归属与复用：CustomerQueue 仍唯一拥有排队顺序和槽位；复用 FacilityLayout.Route 的当前障碍导航及 CustomerWalkPath 的安全平滑，不创建第二套寻路网格。
- 状态归属：目标取实时 QueuePositions，公共门口只负责穿门约束；删除未再使用的固定 queueEntry 缓存，保留 Configure 参数兼容调用方。
- 依赖方向：已提交布局和队尾 → 队列路线 → 角色位置/朝向，不写设施、钱包、订单或存档。
- 兼容与失败：无布局导航的独立队列保留 ShopLayout.Walk 回退；旧档无需重建或迁移。布局编辑仍由既有暂停/确认流程管理。
- 自动防线：复现旧 compact 布局过门折返；验证无效入口点不会被访问、移动旋转后公共入口与新槽位、实际障碍绕行；回归 CustomerQueue、063、071、083 路径/朝向及隔离 Play。运行 check-boundaries.sh。
