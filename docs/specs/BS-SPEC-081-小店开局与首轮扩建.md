# BS-SPEC-081：小店开局与首轮付费扩建

- 版本：v1.0；日期：2026-09-22；状态：本地实现及定向自动验证完成；自然试玩体验待确认。
- 用户要求：开局不应有这么大地方，截图方格区域后续随升级花钱开放。
- 前置：[080成长修订](BS-SPEC-080-首单晋级与经营成长修订.md)，已有058装修/商城、064附属房门控、自由摆放与077/078多槽。
- 范围：重组现有30×30大厅的开放过程，不增加新房间、玩法或产线。本规格只形成开发交接，不执行开发。

## 1. 证据与设计目标

[用户试玩截图](opening-playtest-reference/opening-too-large.png)显示大面积已铺装厨房。`RestaurantArchitecture` 将主厅 x=1..14.6 全宽铺为 KitchenTiles，`ShopLayout` 开局仍是30×30大厅；064只关闭外部附属房，并未缩小大厅。故仅删绿色标记或隐藏房间不能解决这次问题。

目标：开局一眼能联系“机器、柜台、顾客、收钱”；达到员工阶段时，让玩家用已经学会的经营收入买到明显变大的空间。初始保留完整可营业设施，不把额外土地做成卖首单/清桌所需前置。

## 2. 空间开放

### 新档起步区

- 初始可经营大厅约为原面积一半，建议矩形 x=-15..8、z=-15..5，共23×20＝460平方世界单位（原900的51%）。确有设施碰撞冲突时开发可调整边界，交付仍控制在原面积55%以内，保留必要通路。
- 保留原主入口及门外街道位置，重新布置**新档初始设施**和室内队列，不使用假墙把旧工作点封在外面。
- 起步区容纳1机器、1柜台、原队列、收钱点、玩家升级入口；Lv2出现2张基础双人桌和垃圾桶，全部在已开放地面内。
- 建议新档机器中心(4,1.5)、柜台(-3,0)、两桌(-8,2)/(-8,-2)、玩家升级点(5,-9)，坐标均为XZ示意；实际根据设备体积/服务站位避让。具体坐标是可逆实现细节，不要求照搬导致碰撞。
- 动线保持主通路净宽至少2.5，顾客从原门进入再排队，不穿员工点；首单、用餐、清桌、倒垃圾和属性升级都无需穿越未买区域。
- 相机用当前已开放区域和必要入口构图，不远拉到整块未营业场地；不重调全局移动速度，不遮挡交互。

### 预留区与扩建

- 剩余大厅是“一次性主厅扩建”，不是十几个逐块收费地砖。初始用低墙/施工隔断表达边界，不呈现已装修且能走进去的大厨房；远期仅保留轻量轮廓和简短说明，不铺整片棋盘格冒充已开业。
- Lv1–2：只能预览 `Expand at Lv.3`，入口不可付款；同时告知用途：更多设备空间与员工办公室通路。
- Lv3：开放 `Expand main hall`，总价 **150金币**，支持现有分次投入；面板明确 `More working space · Staff access · +2 stars`。
- 投满后剩余大厅一次开放、隔断撤去、地板和墙体装修连贯，获得 **2星一次**；总外轮廓回到原30×30，不再次挪动起步设施。
- 达Lv3仅开放购买资格，不免费赠送大厅；玩家可先继续在小店经营/升级再买。新档HR办公室需“Lv3且主厅已扩建”才打开，首雇仍50，总首次员工投入150+50=200；雇佣本身仍按当前规则，不额外赠星。
- 之后附属区沿用既有等级与价格，但新档必须先完成主厅扩建才能接通相应入口；UI同时显示土地前置，不能只写达到等级即可使用。玩家可以靠已有升级提前升店铺等级，未购土地时已有小店继续营业。
- 卫生间、饮品侧翼、西侧等既有费用不改；本次不把所有原本免费房间一并重定价。商城完整开业报价把尚未支付的主厅剩余款单列，已购买时不再重复计入。

## 3. 地面、布置与交互的同一事实

- 当前已购区域同时决定：可装修、可放设施、可通行/寻路、操作点合法性和相机有效构图。不能只隐藏贴花但允许玩家/员工穿过，也不能只禁摆放而NPC穿墙。
- 安全底层碰撞继续存在，防止坠落；锁区用正确边界阻挡，不通过删除所有地面制造掉落。
- 出生点、现金生成、临时道具、默认设施和预留投放点都不得在锁区。缺合法摆放位置时不扣设施款，不把设备放进锁区或街道。
- 原摆放、门口进出、服务点路径校验继续生效；付款建设时如果玩家贴着边界，不弹飞/夹住角色。扩建取消/离开只暂停投入，已付款不丢失。
- 施工牌可以显示下个目的地，但不恢复满屏任务箭头。只能展示真实开放等级、剩余金额及用途。

## 4. 存档与旧店兼容

- 新增主厅扩建状态与累计投入，归属于每个经营槽；开新槽时默认未购。采用实施时下一空闲schema，保留077/078和未来版本拒绝规则。
- **所有本规格之前的旧档默认主厅已开放**：保留已经使用的全大厅、自定义摆放、已开房间，不追收150、不补发扩建2星、不移动设备。不能把用户正在经营的店突然缩小。
- 因此用户测试“新小店开局”应在现有多槽界面新建隔离测试槽；不要删除或重置原槽。旧低等级档仍获得080成长修复，空间按历史已获得权益保留。
- 历史主厅资格与旧版legacyAccess分清：本次只保留旧主厅/相关可达权益，不把所有新建槽永久赋予全部未来设施资格。
- 新版小店档部分付款、完成建设、获得2星及购买结果一起保存；重复加载、切槽、恢复、重复确认不会重复扣款发星。失败处理沿用现有事务协调，不用UI维护第二套“已买地”。

## 5. 经济与可玩性依据

150金币为本次**产品建议新增地价**，不是原游戏测得值。它购买真实新增面积和后续工作通路，保持小店原有收入；不引入租金、维护费或原料费。

完整对比：旧Lv3首雇需50，现在新档先扩厅150再雇50，共200；新增缺口最多150。T_cash≈max(0,200-余额)/当前有效净入账速度，必须实测收入才有时间值。初始距离变短可能提高入账速度，不能只用新增150推断节奏一定变慢。

卖首单和Lv2清桌都不依赖土地，且小店持续可服务，因此没有“必须扩建才能赚到扩建钱”的环。若试玩显示Lv3存钱长时间无进展，先检查收入/提示/地块价值，再局部评估150价格；不同时抬高设施价或减慢生产。无需本次新增加速器。

## 技术边界与方案审查

- 实施边界：`MainHallExpansion` 独占主厅购买、累计投入及区域；`ShopLayout` 提供起步设施坐标，`FacilityLayout` 使用同一已购区域的内缩安全边界；建筑装饰只读取区域。`RestaurantPersistence`/启动入口在实例化前读取目标槽，v18 保存 `compactStart/mainHallBuilt/mainHallInvestment`；v17 及之前保留全厅，Restore 不发星。

- 归属与复用：复用现有扩建购买/装修/布置入口；补齐同一个“已开放主厅区域”的查询，不让地板、导航、摆放、HUD各写一套坐标判断。
- 状态归属：地块购买与投入由扩建域唯一维护，持久化只保存快照；成长模块订阅建设成功发星一次。建筑生成只读结果，不在生成/Restore时当作新购买。
- 依赖方向：地块状态→空间查询→建模/摆放/导航/提示；依赖现有会话生命周期。不会把保存或UI按钮引入纯几何判定。
- 兼容与失败：新档布局与旧档恢复入口明确区分，Hydrating按目标槽直接生成对应店面，不先运行错误世界再补救；旧全厅档不重排。
- 自动防线：开局合法工作点、禁止锁区放置、建设一次性、加载/切档隔离，以及现有代码边界脚本。开发补充具体实现责任，不另建泛用世界引擎。

## 7. 本地验收

1. 新槽Lv1：实际可经营大厅不超过原面积55%，多余方格区不能走入或摆放；机器/柜台/玩家升级点均可达。
2. 在未买地状态自然完成首单、Lv2用餐/清桌/主机升级，能达到Lv3；顾客不穿隔断、不掉落。
3. Lv2不能付地款；Lv3携带100投入后余50未开；再得60完成建设后余额10，区域开放、星+2一次；保留起步设施原位。
4. 主厅已买且Lv3，HR可进入、正常花50雇人；重复开面板不再扣地款。未来设备/房间前置文案与实际一致。
5. 锁区没有现金、道具或默认设备生成；扩建后导航/摆放/装修一致，原入口及清洁/供货路径继续可用。
6. 旧全厅自定义布局档不收费、不缩小、不补星；新小店半付款档重开保留投入，交替切槽不互相污染。
