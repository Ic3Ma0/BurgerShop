# BS-SPEC-086 全界面中文与文字适配

- 用户要求：游戏内所有英文改为中文，字号合理，不超出 UI。
- 范围：HUD、商城/摆放/失败提示、设施/人物升级、餐桌换款、存档与删除确认、离线结算、互动提示、招牌/道路/订单文字。数字和通用图形符号保留。
- 使用简洁的简体中文；金额、等级、产能、库存、解锁条件保持原始值。不改变购买、解锁、暂停、存档字段或对象标识。

## 技术边界与方案审查

- 归属与复用：沿用 HudChrome 和已有 Noto 中文字体。新增只负责展示的中文文案表与 Text 展示适配；玩法产生的字符串和内部英文标识保持稳定，最终展示使用中文，避免把商店 ID / Find 路径 / 存档键误翻译。
- 状态归属：文字组件只拥有原文缓存、译文和排版；数值与业务状态仍由既有系统管理。世界文字单独适配字体与招牌宽度，不驱动经营。
- 依赖方向：玩法文案 → 中文展示 → Unity 排版。不从翻译层读取场景经济、改变订单或保存数据；不增加联网翻译或外部依赖。
- 兼容与失败：沿用旧档、对象名、回调、按钮点击区域和已有中文开局提示；未覆盖英文不能静默删除，测试检查遗漏。沿用现有字号意图，取消强制 28 字号，以换行/适度缩小适配而非只靠裁剪隐藏内容。
- 自动防线：文案覆盖检查、数值保留、字号/文本边界断言；隔离 Play 检查新旧游戏阶段、商城分页、属性/设施卡、存档/确认/离线窗，横屏与竖屏截图检查。运行 check-boundaries.sh；Android 仍留后续统一验收。

## 验收

1. 以上玩家可见文字均为中文，内部对象名及存档格式不改变。
2. 横竖屏下标题、按钮、说明和大额金币完整位于容器内，不与按钮/卡片相邻行重叠。
3. 对长提示适当分行、缩小字号；保留费用、差额、收益、删除后果等关键信息。
4. 升级/关闭/返回/删除确认等行为保持正常；中文字体具备所需字形。
