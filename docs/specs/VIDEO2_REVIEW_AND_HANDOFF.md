## 参考材料及证据边界

来源：用户提供的 [视频2.mp4](../../../视频2.mp4)，时长约 6 分 54 秒，432×960。按时间段抽帧并对关键经营片段加密查看；并非每帧测量，也未作音频节奏分析。以下时间均为近似定位，截图供快速查证，以原视频连续动作复核为准。

录像没有明确版本号，不能用它证明“当前商店最新版本”的全部规则。中间水排序等广告画面不属于经营玩法。当前视频未展示完整奶茶制作流程，因此本轮不给饮料生产线编造规则。

### 1. 解锁是逐步投资，而非攒够全款

约 00:38，设施区域显示 230，钱包为 211；约 00:41，钱包为 0，区域还差 19。玩家离开收钱，约 01:21 完成建设。这是明确可观察的分次投入。

证据：[00:38](video2-evidence/v2-038s.jpg)、[00:41](video2-evidence/v2-041s.jpg)、[01:18](video2-evidence/v2-078s.jpg)、[01:22](video2-evidence/v2-082s.jpg)。

本地 [FacilityUnlockZone.cs](../../Assets/_Project/Scripts/Restaurant/FacilityUnlockZone.cs) 要求有全款、停留 1.5 秒后整体扣除，资金不足时不会积累投入。对应 023；保留 BurgerShop 设施价格，不照抄参考游戏的 230。录像未验证重启是否保留投入，本版持久化属于主动补全。

### 2. 顾客要的是一笔订单，不总是一件商品

录像约 00:06、00:34 可见堂食需求 3，其他时段出现不同数量；约 04:08–04:10 可见车辆需求 2 盒。数量需求让一次搬运的容量、柜台存量与服务节奏产生关系。

证据：[04:08](video2-evidence/v2-248s.jpg)、[04:10](video2-evidence/v2-250s.jpg)。

本地 [CustomerAgent.cs](../../Assets/_Project/Scripts/Customer/CustomerAgent.cs) 的订单固定为 1；[BurgerServingZone.cs](../../Assets/_Project/Scripts/Restaurant/BurgerServingZone.cs) 每次消费一个便让顾客离队；[DriveThruLane.cs](../../Assets/_Project/Scripts/Restaurant/DriveThruLane.cs) 每车一盒，且开始交付时即记录成交。对应 024：逐件交付，最后一件到达才结算。数量概率、收入按件计算、具体间隔是建议值，录像不足以还原原作完整经济公式。

### 3. 打包是可见的工作台流程

约 01:02、04:02–04:07 可见工作台的散装食品与盒装堆叠，随后玩家取盒搬到窗口。原料、成品和搬运之间存在可见的中间状态。

证据：[04:02](video2-evidence/v2-242s.jpg)、[04:08](video2-evidence/v2-248s.jpg)、[04:10](video2-evidence/v2-250s.jpg)。

本地 [BoxingStation.cs](../../Assets/_Project/Scripts/Restaurant/BoxingStation.cs) 直接转换手持食品，未体现台面输入和输出库存。对应 025。是否可以无人加工未被本录像可靠证明，规格采用有人操作的明确默认规则。

同时发现 [RestaurantWorker.cs](../../Assets/_Project/Scripts/Restaurant/RestaurantWorker.cs) 在打包解锁后对手持散装优先选择打包任务，即使车道尚未购买。这是源码中的明确分支，可能使堂食断供；本轮未运行复现，不能称为已观测的运行故障。025 将防止两条供货线互相饿死纳入验收。

录像显示更长队列、特殊顾客及临时加成等，但本轮不足以确定完整触发与奖励规则。先完成已有经营链，再分别设计。广告插入和常驻广告条不能仅凭出现次数推导真实广告策略；不照搬到当前原型。

## 验收与交付原则

- 先完成数据正确性，再确认操作与画面。重点为金币投入原子性、订单唯一结算、物品守恒以及员工持续服务。
- 开发核对实施时存档最新版本，保留旧校验和旧购买权益；不重置存档来规避迁移。
- 各 Spec 都包含可复现的真机步骤。Editor 测试、Play 验收、APK 构建、手机验证分别记录；无法运行某项便明确标为未验证。
- 参考截图仅用于需求文档，不引入游戏 Assets、应用品牌或发行素材。
- 本轮没有声称全部差异已覆盖，尤其美术、镜头手感和当前版本 UI 需要本地运行录像做进一步对照。当前三份规格集中解决可从源码和参考视频直接定位的经营规则差异。
