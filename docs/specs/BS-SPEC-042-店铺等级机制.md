# BS-SPEC-042 店铺等级机制 v1.1

用户授权：2026-09-13「你来进行修订，然后进行开发吧」。本文件取代外部 v1.0 的冲突规则；仅作用于店铺等级，不改 041 或任何设施标价。

## 晋级顺序

每行是「当前级完成的里程碑 → 晋级后开放」，不是先完成尚未开放的功能。所有目标数量为 1，完成事件永久记账；员工操作同样有效。

1→2：完成柜台汉堡订单 → 堂食桌椅、用餐、小费与清理（完整流程一起开放）。
2→3：清走用餐后产生的桌面垃圾 → 雇工。
3→4：员工完成一次自动服务订单 → 第二烤台与第二柜台建造。
4→5：第二烤台产出汉堡 → 蓝盒打包。
5→6：加工完成一个蓝盒 → 汽车取餐。
6→7：完成一份汽车订单 → 可乐侧翼及其中的桌型建设。
7→8：完成可乐订单 → 骑手区域，先手动供给红盒。
8→9：完成骑手订单 → 汉堡→红盒→黄色取餐箱传送带自动化。
9→10：自动化开启后完成骑手订单 → 免费开放西侧纸袋区的建造资格（设施仍付原价）。

第二烤台等属于新的经营能力/协作方式，并非新增输入动作。里程碑禁止用重复售卖次数填充等级；不承诺每级都发明全新动词。

## 星星与双门槛

Lv.1..9 晋级需里程碑已完成且持有星数达到 4+2*(rank-1)，晋级扣星、余量保留。里程碑首次完成 +2 星；既有设施升级 +2 星保留；玩家/员工属性每次升级也 +2 星，使规模门槛不依赖有限的机器梯子。发星只跟随成功购买，不跟随恢复/迁移。

需求累计108星；九个里程碑18星，玩家40次属性升级80星，主烤台4星、主柜台4星，早期可用的餐桌升级与后续机器、员工属性提供余量。餐桌现有三选一不改变价格，成功选择首次 +2 星。每个等级必须先能由已开放来源凑足需求；测试检查每段来源预算。

## 循环等级

Lv.10→11 起只付金币，不扣星、不要求额外里程碑。当前rank=r时成本500+250*(r-10)，长整型计算并在int金币交易边界饱和，不发生溢出。采用线性而非无限指数增长，以免成本远超效率。

每升一级，所有新产生的经营现金（柜台/堂食小费/汽车/纸袋/骑手）增加基础金额的2%，加法叠加；设施单价保持原值，旧地面现金不重算。不足1金币的奖励余数按1/50金币累计并存档，达到整数再发，不丢小额收益。零件不加成。招牌显示等级和收益加成，每次循环晋级颜色与等级文字变化。等级无设计上的MAX；达到整型表达极限拒绝再加，防溢出。

## UI

复用左上角星级入口及现有升级面板，不恢复中央任务胶囊。左上角显示等级、星数/要求或金币差额，条件齐备显示Ready。点开显示唯一里程碑、完成状态、缺星/缺钱、下一等级解锁；奖励预告与条件同时满足才允许晋级。

进度未满时显示真实比例，条件满时隐藏填充条并显示Ready/待完成任务，不画假的99%。循环阶段展示真实金币缺口。不再出现店铺MAX。西区到Lv.10自动免费开放，不再占用升级按钮；旧档已开西区不回收。

## 解锁与兼容

基础三套餐桌从Lv.2可用（保持原有免费基础家具，不补收钱），HR建筑位置保持，Lv.3开放雇用；已购买设施、投资金额及已有员工永不回收。玩家属性从开局可升。其它设施使用上表门槛；独立无等级追踪器的测试组件维持旧独立行为。

存档13→14，增加milestoneMask、legacyAccess、incomeRemainder。位i代表从等级i+1晋级的里程碑；新档0。旧档迁移完成1..当前等级对应目标（用户原方案的宽松兼容，明确豁免当前关），不补发星星。旧版所有原本可用能力保留：legacyAccess=true永久保存；旧玩家仍需完成后续可重做的里程碑。已有数据不足的任务允许以已建第二烤台、正常运行的产线再次产生完成事件。只对旧版本执行一次迁移；v14严格读回，不重复豁免。

所有v1..13校验和字节格式保留。新字段参与v14校验和，非法位图/余数拒绝。等级不降低，金币、零件、041等级及设施记录保留。事件一旦记账即请求存档；读档不发奖励。

## 验收与节奏

覆盖双门槛分别不足、成功扣费、重复点击、九段先决条件可达、所有事件接入、旧档迁移/二次读档、循环成本/收益/余数/溢出、无MAX的UI、新档门控和旧档保留、原5个任务测试对齐、全部EditMode。可视验证采用隔离存档；Android不执行。

服务比率时钟与开放回路，前段探索能力、后段规模，不新增独立货币/广告/离线。T(n)=缺口/实际金币收入率；循环加成会改变收入率，真实T(n)需实测，不编秒数。没有强制倒计时，仍可经营；长线等待体验不能仅靠静态公式证明。I3由真实下一目标和Ready代替满级；I7不涉及。
