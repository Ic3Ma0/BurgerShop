# BS-SPEC-076 任务系统适配星星门（补齐 Lv.10–15）

- 版本：v1.0
- 状态：**已完成**（本地定向 EditMode；已纳入本地提交 `0e93618`）。用户已确认按本 spec 开发。
- 开发时基线（历史）：BS-SPEC-075（星星门已落地）
- 优先级与原因：**高**。星星门覆盖 Lv.1–15，但任务只覆盖 Lv.1–9；**Lv.10–15 有门槛、无引导**——玩家需在此攒 90 星（占总供给 36%），却没有任何任务提示星从哪来。
- 前置依赖：BS-SPEC-075
- 用户已确认：任务需更改以适配等级机制（用户本轮明确指令）
- 关键未定项：见 §5（三项）

---

## 1. 目标与非目标

**目标**：让任务系统与星星门**同覆盖、同语义**——Lv.1–15 每一级都有一个引导任务，且每个任务都指向一个**具体的星源池**，使玩家在完成任务的过程中自然攒够升下一级所需的星。

**范围内**

1. 新增 **Lv.10–15 的 6 个任务**（§3.1），每个指向一个不同的星源池
2. 明确里程碑语义：**从"升级门槛"改为"教学 + 星源"**（门槛已在 075 改为星星）
3. 任务胶囊优先级固化（§3.3）
4. 里程碑位图从 9 位扩到 15 位（存档 v15）
5. 修正 `AddIncomeBonus` 的基数不一致（§3.4）

**非目标**

- 不改星星门本身（075 已定：`StarCap` 曲线、Lv.16 切换点、`StarSupplyCap=248`）
- 不改任何价格、属性线成本曲线、离线收益
- 不新增广告 / 内购
- 不删除既有 9 个里程碑（降级保留为教学 + 星源）

## 2. 现状（实施前须核对）

| 事实 | 位置 |
|---|---|
| `Goals(rank)` 对 `rank >= 10` 返回 `Array.Empty<ShopGoal>()` | `ShopRanks.Goals` 的 `default` 分支 |
| `MilestoneMask = (1 << (ContentEnd - 1)) - 1` = **9 位**（`ContentEnd = 10`） | `ShopRanks` |
| 星门覆盖到 `StarGateEnd = 15`，循环从 `CycleStartRank = 16` | `ShopRanks` |
| `RecordMilestone` 依赖 `Allows(stage) => rank >= stage`，即**任务可补做**，不会因跳级永久丢失 | `SessionGoalTracker` |
| 任务胶囊优先级已是：开局引导 → 可升级 → 任务 → 经营杂务 | `SessionGoalTracker.CapsuleTitle` |
| `+2 ⭐` 已贴到 12 处 UI | `StarRewardCopy` 的全部引用 |

**核心缺口**：Lv.10–15 期间 `Goals()` 为空 → 任务胶囊在星不足时只能回落为经营杂务提示（"Pick up a burger"），**与升级目标脱钩**。

---

## 3. 规则

### 3.1 新增 6 个任务（每级指向一个不同星源池）

| 等级 | 任务文案 | 判定条件（可断言） | 指向的星源池 | 池容量 |
|---|---|---|---|---|
| **Lv.10** | Get any stat line to Lv.10 | `max(playerSpeed, playerCarry, staffSpeed, staffCarry) >= 10` | 四条属性线（首次发现） | 160 |
| **Lv.11** | Get all four stat lines to Lv.8 | `min(同上四条) >= 8` | 四条属性线（广度） | 160 |
| **Lv.12** | Get a staff line to Lv.12 | `max(staffSpeed, staffCarry) >= 12` | **员工线**（最易被忽略） | 80 |
| **Lv.13** | Upgrade any facility again | 任一 `GrowthUpgrades.TryBuy` 成功 | 设施升级 | 36 |
| **Lv.14** | Choose a set for all six tables | 6 张 `TableUpgradeZone` 的 `SetId != Starter` | 餐桌换款 | 12 |
| **Lv.15** | Get any stat line to Lv.18 | `max(四条) >= 18` | 属性线收尾（接近上限） | 160 |

**设计意图**：6 个任务**故意不同型**（深挖 / 广度 / 冷门池 / 设施 / 餐桌 / 收尾），避免"6 级做同一件事"。玩家做完这 6 个任务的过程，本身就是攒到 Lv.15 所需 90 星的过程。

### 3.2 里程碑语义

- **不再是门槛**（门槛是 `Stars >= StarCap`，075 已实现）
- **保留两个职责**：① 教学——指示刚解锁的内容怎么用；② 星源——完成 +2⭐
- **可补做**：`Allows(stage)` 逻辑保持，跳级不会永久丢星

### 3.3 任务胶囊优先级（固化，不改结构）

```
1. 开局引导（Opening.IsActive）
2. 可升级  → "Tap Lv.N Ready"
3. 本级任务（未完成时）—— Lv.1–9 教学里程碑 / Lv.10–15 新增任务
4. 经营杂务（ShowLoop：取餐/送餐/清理/打包/收银）
```

**关键不变式**：任意时刻胶囊必须有内容（I1）。第 3 层未完成时**优先于**第 4 层。

### 3.4 顺带修正：Lv.10–15 的"下一级"文案与实际加成不符

```csharp
// ShopRanks.NextUnlock —— 对 rank >= ContentEnd(10) 返回固定文案
return rank >= 1 && rank < ContentEnd ? labels[rank-1] : "+2% cash income & shop sign";
```

但 `AddIncomeBonus` 的实际加成是**递增**的：`+2% × (rank - ContentEnd)`

| 等级 | Lv.11 | Lv.12 | Lv.15 | Lv.16 |
|---|---|---|---|---|
| 实际加成 | +2% | +4% | **+10%** | **+12%** |
| `NextUnlock` 文案 | "+2%" | "+2%" | **"+2%"** ❌ | **"+2%"** ❌ |

**而 `SessionGoalTracker:48` 把 `NextUnlock` 当作"该等级无任务时的回退文案"**：

```csharp
return listed!=null&&listed.Length>0 ? listed[0].Title : ShopRanks.NextUnlock(rank);
```

**Lv.10–15 的 `Goals()` 恰好为空 → 玩家在这 6 级看到的正是这句错误数字。**

**修正**：`NextUnlock` 对 `rank >= ContentEnd` 返回**动态**文案 —— 下一级的实际加成：
```csharp
$"+{2 * (rank + 1 - ContentEnd)}% cash income & shop sign"
```
即 Lv.10 → "+2%"、Lv.11 → "+4%"、Lv.15 → "+12%"。

> 注：`GrowthUpgradeHud` 的收入文案是**动态且正确**的（`2×(rank-10)% → 2×(rank+1-10)%`），不需修改。问题只在 `NextUnlock` 这一处。

## 5. 关键决策点

| # | 决策 | 选项 | 推荐 |
|---|---|---|---|
| **D1** | Lv.10–15 任务的判定方式 | **阈值型**（"升到 Lv.10"）/ 动作型（"升任意一条线"） | **阈值型**：动作型会让 6 个任务退化成同一件事；阈值型可自查进度 |
| **D2** | Lv.15 的任务强度 | 「任意线到 Lv.18」/「四条线全部到 15 级」 | **前者**：后者需 60 次购买，过重 |
| **D3** | 是否给 Lv.10–15 任务加"完成后额外奖励" | 不加（只给 +2⭐）/ 额外给金币 | **不加**：保持"星 = 唯一进度货币"的纯粹性，避免引入第二激励 |

## 6. 边界、存档与兼容

| 情况 | 预期行为 |
|---|---|
| **存档 schema** | 里程碑位图从 9 位扩到 **15 位** → **必须升版本到 v15**；`MilestoneMask = (1 << 15) - 1` |
| 旧档（v14 及更早） | 新增的 6 位默认 0；**等级、星、金币均不回退**；`CompletedThrough` 迁移逻辑需相应扩展 |
| 旧档已过 Lv.10 | 新增任务可**补做**（`Allows` 逻辑），不会因"已过级"永久拿不到那 12 星 |
| 任务条件未达成 | 胶囊显示该任务；不影响买卖与升级 |
| 6 张餐桌未全部解锁 | Lv.14 任务条件不可达成 → 胶囊回落为经营杂务（不得卡死） |
| 重复完成同一任务 | `milestoneMask` 位已置则跳过，**不重复给星** |

## 7. 验收标准（每条机器可判定）

| 编号 | 初始状态 | 操作 | 必须出现的结果 |
|---|---|---|---|
| **AC-01** | 任意 | 读取 `Goals(10..15)` | 各返回 **1 条**任务，且 `Kind` **互不相同**（EditMode 断言） |
| **AC-02** | 任意 | 读取任务判定表 | 15 个任务的 `Required` 均为 1；判定条件与 §3.1 一致 |
| **AC-03** | Lv.10，四条属性线最高 9 级 | 升到 10 级 | `milestoneMask` 第 10 位置位；`Stars` **恰好 +2** |
| **AC-04** | Lv.11，四条线为 7/8/7/8 | 把最低一条升到 8 | 任务**不完成**（`min >= 8` 未满足）；再升另一条到 8 后才完成 |
| **AC-05** | Lv.14，6 张桌中 5 张已选款 | 第 6 张选定 | 任务完成，+2⭐ |
| **AC-06** | Lv.14，仅 3 张桌解锁 | 观察胶囊 | 胶囊回落为经营杂务文案，**不卡死、不报错** |
| **AC-07** | v14 旧档 | 读档 | 等级/星/金币不回退；新增 6 位为 0；可继续升级 |
| **AC-08** | 任意 | 重复触发同一任务动作 | `milestoneMask` 不变，`Stars` **不重复增加** |
| **AC-09** | Lv.1–15 任意等级 | 观察任务胶囊 | **始终有内容**（不得为空、不得只显示 `Lv.N`） |
| **AC-10** | 任意 | 调用 `NextUnlock(10..15)` | 文案中的百分比**递增**：Lv.10→`+2%`、Lv.11→`+4%`、Lv.15→`+12%`；**不得出现固定 `+2%`**（EditMode 断言） |
| **AC-11** | 本 spec PR | 查看 diff | 未改星星门常量、未改价格、未改离线收益、无新增广告/内购 |

**不应破坏的既有行为**：BS-SPEC-075 的星星门与 `+2 ⭐` 显示、BS-SPEC-041 的 20 级属性线、9 个原有里程碑、存档 v14 及更早的兼容。

## 8. 附：与内核不变量的对照

| 不变量 | 本 spec 的满足方式 |
|---|---|
| **I1 目标常在** | AC-09 断言：Lv.1–15 任意等级胶囊**必有内容**；Lv.10–15 从"无任务"变为"指向星源池的任务" |
| **I2 没有死路** | AC-06：任务条件不可达成时回落经营杂务，不卡死 |
| **I4 变化可感知** | 任务完成 → `Milestone +2 ⭐` 世界反馈 + 星条跳动 |
| **I5 改写而非并列** | 新任务**指向已有系统的深化**（属性线 / 设施 / 餐桌），不是新增面板或货币；D3 明确拒绝引入第二激励 |
| **I8 停止由玩家决定** | 任务完成 ≠ 可升级；星条仍是真实门槛，两个目标同时可见 |

**风险提示**：新增任务判定属"反先验"约束（模型默认倾向动作型任务）。实测反先验规则遵守率约 70%，因此 **AC-01/02/03/04/10 必须落成 EditMode 断言**。
