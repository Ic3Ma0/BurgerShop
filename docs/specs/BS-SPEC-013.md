# BS-SPEC-013：柜台出餐、入座用餐与顶部任务 HUD

- 版本：v1.6
- 状态：开发中
- 对应基线：已验收 MVP **0.1.2**（Goal 00–09）
- 优先级与原因：用户用三张参考图批准本刀。把「手里汉堡直接塞给队首、顾客走到绿块消失」改成柜台库存 + 白圈收银 + 桌子用餐，并换成顶部星星 / 金币 / 任务胶囊布局。
- 前置依赖：无其他 spec。依赖现有烤台、绿区取餐、队列、钱包、升级、雇佣。
- 用户已确认：三张参考图即产品批准；本刀不在 010 / 011 / 012 中点选，也不再二次确认。
- 产品建议或关键未定项：桌子开局预置三张（共 6 座位），不做买地块解锁。任务胶囊文案由开发按当场循环选择英文短句（见下表）。白圈与放餐点可重叠或紧邻，由开发按现有柜台坐标决定。排队仍最多 3 人占位，但不再绘制 `QueueSlot_*` / `CustomerEntrance` 四块无用地面方块。

## 目标与范围

玩家目前是：绿区取餐后站上金色圆盘，把随身汉堡交给队首；顾客拿完沿预设出口走开并在绿块处消失。顶部是多行状态字。

本次之后：烤台出餐 → 绿区取餐 → 把汉堡放到柜台（柜台可见库存）→ 顾客在柜台排队 → 玩家（或站在白圈里的人）把柜台上的汉堡交给队首 → 顾客走到桌子坐下吃约 3 秒 → 离场。顶部为星星进度、金币、当前任务胶囊。

希望解决：交付不像柜台作业、顾客没有用餐步骤、首局看不出当前目标。

本次交付：

- 店内预置三张可用桌子（每张红桌 + 两侧座位，共 6 座位），顾客用餐后离场。
- 柜台可放置汉堡，无数量上限，有可见份数（份数很多时用若干代表物 + 数字）。
- 柜台旁地面有白色虚线圈；站在附近才能从柜台出餐。
- 成交仍是每位顾客一个汉堡；出餐掉 10 纸币（金币改由玩家走过拾取，见 [BS-SPEC-016](BS-SPEC-016.md)）；`servingInterval` 仍由玩家与员工共享。
- 雇佣后的员工把汉堡放到柜台，再在白圈按同一套收银规则出餐（不是绕过柜台直接塞给顾客）。
- 运行时 HUD：左上金色星星 + 圆角绿条 `n/15`、右上钞票图标 + 粗体金币（不要 IAP「+」）、上方中央圆角任务胶囊（白/浅绿底或完成时变绿打勾，底部 `n/n`，完成时可短暂星点庆祝）。金币 / 星星 / 柜台份数 / 任务进度在数值增加时短放大回弹，见 [BS-SPEC-018](BS-SPEC-018.md)。不挡左下摇杆，不改 `VirtualJoystick`。默认不显示携带/顾客多行字。
- 任务、柜台库存、桌子占用都是会话状态，不写入存档。

本次不做：

- 不改单价 10、烤台升级 30/60、默认出餐时间、手持上限 4。烤台库存按等级 **4 / 6 / 8**（见 [BS-SPEC-019](BS-SPEC-019.md)）。雇佣人数与场地尺寸由 [BS-SPEC-015](BS-SPEC-015.md) 更新。
- 不做买地块 / 解锁经济、第四张桌子、第二种商品、第二间店、离线收益。
- 不把 UI 改成中文；不引入 Pizza Ready 名称、截图、模型或商标文案。
- 不改摇杆位置、尺寸、触控；不改 `SafeAreaFitter` 计算。
- 不升 `RestaurantSaveData` 版本，不新增存档字段。

## 玩家流程与规则

入口：`SampleScene` Play 后由 `Goal01Bootstrap` 组装店铺。桌子与白圈开局即存在。

| 项目 | 明确规则 |
| --- | --- |
| 触发条件 | 玩家或员工在放餐范围内且手持 ≥ 1 → 每次间隔至多放 1 个到柜台（柜台无上限）。玩家或员工在白圈内、柜台库存 ≥ 1、队首已就绪、收银冷却结束 → 从柜台交给该顾客并记账。 |
| 费用 / 奖励 / 时长 / 上限 | 出餐掉 **10** 纸币（不改价；金币只在捡到时增加，见 016）。手持上限 4；柜台 **无上限**。用餐 **3 秒**。预置 **3** 张桌子、共 **6** 个座位；满座时后来的顾客在桌边等待再坐下，不要走到绿块消失。收银间隔沿用现有 0.75 秒。放餐间隔沿用取餐量级（约 0.25 秒，每次 1 个）。 |
| 状态变化 | 放餐：手持 −1，柜台 +1。出餐：柜台 −1，队首离开队列，成交 +1，柜台旁掉 10 纸币，`Coins` 不变。用餐结束后面包视觉销毁，顾客沿出口离场。 |
| 与已有功能的关系 | 玩家与员工从**有货的那台烤台**取餐；每台机自己计数，不共享一个库存上限。柜台库存、收银冷却、钱包仍共享。额外搬运者调用出餐不能推进冷却。绿区取餐、烤台升级价 30/60、雇佣价格与停留规则不变。 |

建议循环（写死）：

1. 烤台产出，玩家站上绿色取餐区，最多携带 4 个。
2. 走到柜台，把手上的汉堡放到柜台（库存数字增加）。
3. 顾客在柜台前排队点单（仍最多 3 人占位）。
4. 站进白圈：柜台有货且队首就绪时交出 1 个汉堡，成交 +1，柜台旁掉 10 纸币。
5. 该顾客走向任意空座位，坐下吃饭约 3 秒，然后离场。不得在取餐后立刻走到绿色方块消失。六个座位都满时在桌边等。

员工：取餐后先放到柜台，再在白圈用柜台库存出餐。员工送单数仍在成功出餐时 +1（存档字段含义不变：经员工完成的成交次数）。

## 界面与资源（涉及呈现时填写）

- 入口、显示位置、反馈时机：新 HUD 挂在现有 `SafeArea` 下。顶部有一条蓝色装饰条。左上金色五角星贴在圆角绿色进度条左侧，条上为加粗描边的 `n/15`。右上绿色钞票图标 + 粗体金币数字（成交时短暂 `+10` / 消费 `-30` 闪一下；数字增加时 punch，见 018）。上方中央为圆角任务胶囊。柜台前显示库存数字（份数增加时同样 punch）。白圈画在地面。烤台升级除产能外，要能看见多一块炉面/灯、短震动和弹出的 `LVn`，满级静态 `MAX`（见 018）。排队坐标仍在，但不再生成 `QueueSlot_1` / `QueueSlot_2` / `QueueSlot_3` / `CustomerEntrance` 四块地面方块；烤台旁绿色取餐圆盘 `PickupSpot` / `BurgerPickupZone` 保留。
- 正常 / 不可用 / 进行中 / 完成状态及文案（界面语言：英文）：

| 当场状态 | 任务文案 | 进度 |
| --- | --- | --- |
| 开局（三张桌子已预置） | `Install a table` | 先显示完成 1/1 并短暂庆祝，再切到当前经营目标 |
| 空手，需要取餐 | `Pick up a burger` | 0/1，取到后 1/1 庆祝 |
| 手持 ≥ 1 | `Move to burger counter` | 0/1，放到柜台后 1/1 庆祝 |
| 柜台有货且队首就绪 | `Serve a customer` | 0/1，成交后 1/1 庆祝 |
| 柜台有货、顾客未就绪 | `Wait at the counter` | 显示当前等待，不记假进度 |
| 可重复的后续出餐 | `Serve a customer` | 每成交一轮 0/1 → 1/1 |

星星：开局因预置桌子为 1/15；首次取餐、首次放上柜台各 +1；之后每成交 +1，封顶 15。只是会话内 HUD，不存档、不改经济。

- 参考图或布局说明：竖屏。左下摇杆仍为锚点 `(0,0)`、位置 `(220, 240)`、尺寸 `280×280`。新 HUD **不得进入该矩形及其外侧约 24px 边距**。金币不要 IAP「+」。`raycastTarget` 必须为 false（摇杆除外）。任务胶囊进行中为白/浅底、左侧彩色圆标、英文短句、底部细绿条 `n/n`；完成时变绿、左侧打勾，并用运行时生成的星点做约 1.2–1.6 秒庆祝（缩放 + 散开）。默认屏只留星条、金币、胶囊、摇杆；携带 / 顾客 / 员工多行字默认隐藏。升级与雇佣仅在圈内显示右下短提示。字体用内置 LegacyRuntime，加粗并加描边/阴影。
- 资源交付：沿用占位几何体、`RuntimeMaterials`、内置字体与运行时绘制的圆角/星/钞票/勾。禁止 Pizza Ready 名称、截图、模型、UI 或商标文案；游戏内英文不得出现 pizza。

## 边界、存档与兼容（只写相关情况）

| 情况 | 预期行为 |
| --- | --- |
| 柜台库存再高 | 仍可继续放餐；数字 HUD 显示实际份数（可大于 4）；视觉堆只保留若干代表物 |
| 柜台为空或白圈外 | 不能出餐、不扣手持、不记账 |
| 队首未就绪 / 队列为空 | 不能出餐；汉堡可留在柜台 |
| 两个搬运者同时在白圈 | 同一帧只能成交一单；冷却不因额外调用而推进 |
| 六个座位已满 | 顾客走到桌边等待，任一桌有空位再坐下吃 3 秒 |
| 中途离开白圈 | 出餐中断；已放到柜台的汉堡留在柜台；进行中的冷却继续计时 |
| 切后台与重新进入 | 沿用现有存档：金币 / 成交 / 烤台等级 / 是否雇人 / 员工送单数。柜台库存、手持、顾客、用餐、任务进度重建 |
| 旧存档升级到本版本 | 不新增字段、不升版本。读 version 1 即可继续 |

不新增持久化状态。允许开发自行决定的可逆细节：白圈与柜台的精确世界坐标、虚线圈段数、胶囊庆祝时长（建议 1.2–1.6 秒）、任务在「进行中」时是否把箭头收起（本刀可以不做地面箭头）。

## 验收标准

| 编号 | 初始状态 | 操作 | 必须出现的结果 |

| AC-01 | 新开局，空手 | 观察店内 | 有三张红桌，每张两侧座位；柜台旁地面有白圈；任务先出现 `Install a table` 1/1；不见 `QueueSlot_*` / `CustomerEntrance` 四块地面方块；烤台绿取餐圆盘仍在 |

| AC-05 | 顾客已拿到汉堡 | 等待约 3 秒用餐 | 顾客坐在座位上；吃完后离场；不是走到绿块立刻消失 |

| AC-08 | 玩家与员工同时在白圈且柜台有货 | 同一时刻出餐 | 只成交一单；第二人不能靠连点跳过 0.75 秒冷却 |
| AC-09 | 已雇员工，烤台有货 | 员工跑一趟 | 员工把汉堡放到柜台；出餐仍走柜台库存 + 白圈，不直接从员工手里塞给顾客 |
| AC-10 | 六个座位都已坐 | 第七位顾客取餐 | 在桌边等待，有空位再坐下吃 3 秒；不走进已删除的绿地板消失 |
| AC-11 | 旧 0.1.2 存档 | 读取 | 金币、成交、烤台等级、雇佣、员工送单数保留；柜台为空、任务按当局重算 |

手机相关：vivo S50 竖屏确认白圈可站上、胶囊与星星不挡摇杆、单指仍能走完循环。本实现若无法装机，在开发报告标明未做真机。

不应破坏的既有行为：绿区取餐上限 4（玩家开局携带仍 4）、柜台无上限、升级 30/60 与停留 1.5 秒、成交价 10、Android 使用 `RuntimeMaterials` + `link.xml`（不要 `Shader.Find`）。烤台库存随等级 4/6/8。雇佣档位、最多 3 人与存档 version 2 见 [BS-SPEC-015](BS-SPEC-015.md)。
