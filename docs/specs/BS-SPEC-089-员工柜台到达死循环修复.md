# BS-SPEC-089 员工柜台到达死循环修复

用户反馈员工经常莫名卡住。定位到柜台状态切换的距离矛盾：Begin 在 1 米内直接进入 Serving，但 TickServing 在 0.7 米外要求重新开始移动，0.7–1 米区间会永远原地切换。

## 规则

员工在柜台操作距离之外必须继续移动，不能直接当作已到达。柜台到达与工作检查共用 0.7 米门槛。保留其他工位范围、速度、工作优先级与库存规则；不靠瞬移或清空物品恢复。

## 技术边界与方案审查

- 归属与复用：RestaurantWorker 独占员工状态切换，沿用 Begin/StartTrip/MoveAlongRoute，不新增寻路系统。
- 状态归属：共用柜台到达半径，不新增存档字段或状态。
- 依赖方向：行为读取当前柜台目标与距离，测试通过真实员工推进确认重新进入移动并到达工作范围。
- 兼容与失败：保留任务、手持物品和暂停行为；不改变不可达路径策略，真正没有通路仍需腾出空间。
- 自动防线：0.71、0.85、0.99 米三点回归，修复前确实失败；员工工作、暂停、升级相关回归；check-boundaries.sh。

## 交付

三个复现位置修复前失败、修复后通过。回归 33/34 通过，1 项存档恢复失败经原代码对照仍存在。[详细记录](verification/089-staff-stuck/DELIVERY.md)。
