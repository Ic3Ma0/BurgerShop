# BS-SPEC-082 餐厅人物造型更新

状态：用户已授权人物外观更新；本规格限定视觉范围。

## 目标与范围

玩家、三位员工、顾客使用同一套明快、圆润的餐厅卡通比例，具有脸、手脚、鞋与服饰细节。玩家以高厨师帽、奶油白双排扣厨师服、番茄红领巾及围裙识别；员工保留 A/B/C 原有身份、身高与制服色，以围裙、胸牌形成统一员工身份，各自拥有不同帽饰、发型、配件。顾客至少十二种整套造型，使用不同发型、肤色、衣服版型、眼镜、帽子、包等形成轮廓差异，不能只换颜色。顾客不使用员工胸牌或厨师制服。

造型由票号确定，不消耗玩法随机数；整套造型循环后进一步变换肤色。大胃王和打电话顾客保留既有行为，外形继续体现体型和手机。行走沿用既有四肢动画。所有角色面朝本地 +Z。

不增加角色玩法、性格数值、收集、费用、奖励、升级或存档字段。经济与节奏数值不适用。库存、订单图标、碰撞体、寻路、速度与人物根节点坐标不变。

## 技术边界与方案审查

- 归属与复用：Core 下集中人物外观目录及建模工厂；三类现有角色创建入口调用工厂。复用 RuntimeMaterials 与 HumanoidVisual。将模型和服饰定义从工作/排队逻辑分离，不引入第三方包。
- 状态归属：外观组件拥有生成的材质和合并网格，销毁时释放；HumanoidVisual 只读根节点位移驱动四肢。行为状态仍归各自原模块。
- 依赖方向：角色创建入口 → 外观工厂；外观模块不读取钱包、存档、场景全局或客户/员工状态机，不回写经营状态。
- 兼容与失败：旧档无需迁移，角色重新生成即应用新外观。保留角色根节点、身体命名及四肢锚点，材质随角色释放。制服元数据继续兼容已有雇工测试。
- 自动防线：测试角色可区分、票号选择稳定且不改变随机序列、外观无可用碰撞体、材质/网格销毁、实际创建入口接入与顾客/员工行为回归。运行 check-boundaries.sh。

## 验收

1. SampleScene 中玩家、员工、顾客使用新造型，远景可分辨角色身份。
2. 同屏人物画廊展示玩家、三位员工、十二种顾客；顾客有显著轮廓差异。
3. 旧的取餐、员工服务、顾客排队与销毁资源测试保持通过。
4. 不改变真实存档；本地隔离测试和渲染检查。Android 性能与真机验收延后，不以桌面检查冒充。
