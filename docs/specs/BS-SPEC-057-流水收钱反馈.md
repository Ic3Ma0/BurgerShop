# BS-SPEC-057：流水收钱反馈

- 版本：v1.0；状态：已完成；见 [交付记录](BS-SPEC-057-DELIVERY.md)。
- 用户已确认：大额纸币不再一下收空，要连续流向玩家，并有连续音效与满足感。
- 开发时基线（历史）：17c800c；改善已有收钱反馈，不新增经营系统。

## 行为

- 保留现有 0.85 米拾取范围。小额一包快速到账；同一落点的大钱堆按金额拆成连续批次，约每 0.07 秒飞出一包，飞行 0.30 秒。每批到达才入账，右上角累计数字及绿色纸币反馈连续更新。
- 普通批次 10；开始收取一个落点时按总额适配批次大小，最多约 32 批。单次已有积钱通常在 2.5 秒内收完（持续新增的钱不在此上限内），避免大钱堆变成长时间强制等待。金额尾数精确保留。
- 从钱堆顶部连续取走，钱堆逐渐变矮；压缩过的大钱堆也逐步缩小。飞行使用薄纸币束，不让整座高钱堆一起飞走。
- 音效为短促纸币沙沙声叠加清脆入账声，连续收取时音高小幅上扬后封顶，停顿后恢复。沿用 Sound 开关、音频并发上限与切后台停音。
- 玩家可以走开：不再发出新批次，已飞出的继续追随并到账，余钱留原处。回到附近可继续。建造暂停时收取也暂停。

## 金额与兼容

- 掉落金额、收入加成、升级价与购买价均不变；拆分不重复应用收入加成，不重复算订单。
- 不新增存档字段。沿用既有规则：已入账的钱保存，地面钱与飞行状态是会话临时状态。不得把动画拆分造成的部分余额记成整堆到账。
- 预留在途金额防止钱包溢出；飞行结束时如余额被外部改变导致无法入账，退回原落点，不能吞钱。
- 不锁玩家。改变的是收钱的短间隔反馈，不改长期 T(n) 的成本/产出公式；到账等待由原约 0.18 秒调整为单包 0.30 秒，大额批次总时长目标不超过约 2.5 秒。长期实测 T(n) 取决于玩家收款路线，本刀不编造测量值。无新增梯子/广告，不触及 I3/I7。

## 验收

1. 10 元一包到账；大额（含非整十）和多笔累积均多次入账、逐渐缩小，最终总额精确，重复推进不重复发钱。
2. 1000 元单堆及 200 笔各 10 元堆在约 2.5 秒内收完，过程中可见多包同时飞行，0.5 秒时仍有余钱。
3. 中途走开后余钱不动，在途到账；回来继续；零时间推进不收钱；接近钱包上限不丢钱。
4. 连续音效限频允许正常流水节奏且不在同帧重复；音高封顶/停顿重置，静音仍生效。
5. 本地 Unity SampleScene 隔离预览核对钱堆变矮、薄纸币流与到账反馈；Android 真机留后续统一验收。
