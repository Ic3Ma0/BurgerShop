# BS-SPEC-026：经营界面视觉统一与信息层级

- 版本：v1.2；2026-09-12；状态：0.2.1 本地实现与主要技术验证完成；未完成验收项见交付记录，未合并。
- 基线：本地 0.2.0，见 [023–025 交付记录](BS-SPEC-023-025-DELIVERY.md)；开发开工重新核对最新状态。
- 用户已确认：下一轮升级 UI、美化、打磨手感并增加正反馈。
- 产品建议：明亮卡通快餐店方向，具体颜色和尺寸为建议值。若用户另选视觉风格，先修订本版；布局和信息规则可保留。
- 优先级：P1；与 027、028 构成一轮，先做本项。遵守 [产品交接](../PRODUCT_AGENT_HANDOFF.md)。

## 目标与范围

将顶部厚蓝条、独立风格面板、密集世界文字升级为统一的游戏界面。玩家能快速看到钱、当前目标、订单和升级收益。本次包括 HUD、订单气泡、交互标签、玩家/员工升级面板及摇杆外观；不更换整套场景模型、不新增商店等级或经济规则。

参考基线截图：[0.2.0 真机打包画面](../images/spec023-025/vivo-table-processing-frame.png)。截图显示文字重叠、无背景白色标签与粗重顶部条；不是对当前实时运行结果的重新验收。

## 视觉规范

- 风格：圆润、明亮、有食物主题；背景卡片奶油白 #FFF5E6，主文字深棕 #3E2B25，强调番茄红 #D94B3D，奖励金 #FFC857，成功绿 #26845B。红色用于品牌/重点动作，不兼任全部错误提示。
- 颜色不独自表达状态：成功配勾，锁定配锁，满级写 MAX，缺钱显示差额。黄色区域使用深色文字。
- 全部卡片统一圆角、轻阴影与图标笔触；移除粗黑文字描边和临时字符充当图标。小尺寸图标须能辨认汉堡、盒子、金币、速度、携带、清洁。
- 沿用英文界面。选择允许随游戏分发的清晰字体，随交付记录字体及图标来源/许可；不购买资源作为默认前提。开发可用自主绘制矢量/程序图形制作最终 UI 元件，不能只替换色值便称为完成。
- 延用 1080×1920 参考画布，以下均是设计单位而非物理像素：标题 44、核心数字 40、正文 32、辅助 28；布局不足优先换行或改结构，不无限缩小字体。卡片圆角 24、间距取 8 的倍数。

## 布局与状态

1. 顶部安全区内左右各 32 留白：左侧现有星进度紧凑胶囊，右侧金币胶囊；移除贯穿屏幕的蓝色底条。保留星进度原有含义，不改称店铺等级。
2. 下方单张当前任务卡，宽度不超过安全区 85%，标题最多两行，进度明确；全部顶部 HUD 高度不超过安全区高度 18%。只有真实任务完成事件才播放完成效果，初始化读取状态不冒充玩家刚完成。
3. 金额使用精确整数及千位分隔，不用四舍五入的 K 值误导购买能力；至少容纳 9,999,999。超过宽度可扩宽卡片，不遮左侧进度。
4. 订单气泡统一奶油白底、商品图标和剩余数，锚在顾客/车辆上方；保留 024 逐件递减规则。相互接近时优先显示就绪队首，偏移或隐藏远端气泡，不覆盖正在服务的数量。
5. 远处设施只显示小图标或必要的待建剩余金额；玩家距交互区边缘 2 世界单位内显示详细操作/库存。重叠时当前交互目标优先，其他标签让位；不能把投入中的剩余金额隐藏。待建价格与当前订单不得同时因降噪而丢失。
6. 打包台保留 RAW、BOX 及实际库存，但移除重复 BOX 大字和悬空调试式文字。所有关键世界标签有深浅对比背景，避开角色携带物与工作台。
7. 食品非空或正处于取放区时，在角色附近显示食品总量/当前容量，满时标 FULL；离开且空载 1 秒后淡出。垃圾单独图标及数量，不算入食品容量；混装时可显示汉堡与盒子数量，不误报只有汉堡。
8. 升级面板统一标题、关闭、两张能力卡：图标、当前等级、当前值→下一等级值、价格。速度可显示当前倍率（例如 100%→115%），容量显示实数（例如 4→5），必须取实际升级数据，不能硬编码本例。
9. 可购状态突出价格按钮；缺钱显示 `Need N more` 且按钮不购买；满级显示 MAX、无下一等级价格。一次点击最多买一级，禁止动画或长按造成重复购买。保留现有区域进入/离开、关闭后需重新进入的规则。
10. 面板不遮摇杆操作区，玩家可走出以关闭；面板自身按钮区域阻止穿透，面板外移动区继续可用。不新增全屏强制停顿。按钮热区最小 132×132 设计单位，在 Unity Game View 中核对热区、鼠标模拟操作与显示尺寸。

## 边界与兼容

纯显示改动，不重算钱包、价格、成交、星进度、员工或升级，不新增经营存档字段。视觉层读取真实状态，不自行猜测购买成功。除交互控件外图像和文字不拦截摇杆触摸。安全区以设备报告为准，不用固定顶部黑边。

允许开发自行决定图标的具体曲线、阴影和内部组件结构；不得用新弹窗或新增付费按钮填补空白。

## 验收标准

- AC-01：输出同一存档、同一镜头的改造前后截图：经营 HUD、订单拥挤、打包、升级可购/缺钱/MAX 六种状态；所有组件遵守同一视觉规范。
- AC-02：在 1080×1920、1080×2358、1440×2560 竖屏及模拟刘海安全区检查，关键标签不裁切、顶部占比不超限，摇杆不被面板阻挡。
- AC-03：金币 0、999、12,345、9,999,999 均准确可读；缺钱与 MAX 不可误购；能力前后值与实际升级一致。
- AC-04：走完烤台→堂食柜台→桌子→垃圾桶→打包→PACK→窗口→两个升级房间，记录标签近远变化；关键操作和订单数没有被携带堆叠遮住。
- AC-05：重开旧存档，金币/员工/升级/设施权益不变，不重播伪完成任务；零散调试文字从默认玩家界面移除。
- 本地验收：Computer Use 操作 Unity Play 检查小字、按钮边缘、摇杆与升级面板；多指用 Unity 输入模拟/自动化测试。记录 Game View 分辨率和实际运行截图，不能只交设计图。
