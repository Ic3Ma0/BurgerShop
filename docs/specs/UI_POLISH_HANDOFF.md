## 当前阶段重点：需求驱动的高效功能开发

用户最新澄清：当前优先完成新功能代码和项目开发。产品 Agent 将需求整理为明确、精简、可执行的 Spec；开发 Agent 按 Spec 直接实现，在本地 Unity 做与改动相称的必要验证，满足功能验收后及时交付并推进下一项。

- Spec 围绕目标、范围、实际行为、必要参数、兼容边界及可复现的验收条件，不把每项功能扩成繁琐的测试或平台操作任务。
- 普通逻辑优先针对性自动化测试；需要确认画面、声音或交互时，使用 Computer Use 操作 Unity Play。验证服务于功能完成，不成为独立的长期工作。
- 不为小改动例行安排长时间运行、多套重复录像、全量回归或复杂验收；只有功能风险、失败或新证据确实需要时才增加检查。没有新证据不重复测试。
- Android 打包、安装、手机操作及平台专项验收留到后期，由用户统一安排；不是永久取消，也不在当前每项功能或每批功能完成时自动启动，不阻塞当前交付。
- 保留必要的功能正确性、旧进度兼容与当前功能本地验收。交付清楚说明已实现内容、必要验证和实际问题；历史平台结果保留，不将尚未安排的平台工作算作当前缺陷。


## 范围与完成条件

- 本轮不改经营经济、不新增角色成长系统、店铺等级或广告，也不进行整套 3D 场景和角色重制。因此成品会改善 UI 和动作反馈，但占位模型仍会限制整体美术完成度；模型升级应另列后续任务。
- 保护真实存档、已有本地改动及 _Recovery；不要卸载游戏或清除数据来验证本轮。
- 完成 v1.2 Spec 的本地 AC、相关 EditMode 测试及 Computer Use 操作 SampleScene Play 的可视/交互验收；不等待真机。
- 提供同一存档/角度的前后对照截图、同一路径的前后操作录像，以及带声音的经营录像。视觉目标必须落实在 Unity 实机，不以静态效果图代替实现。
- 回填实际参数、素材来源、验证结果、Unity 场景入口与本地体验步骤、未完成项，并分别说明实现/验收/合并/发布状态。UI 审美和主观手感仍需用户体验反馈，自动测试只能验证规则和边界。
