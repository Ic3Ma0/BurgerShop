## 目标与范围

离线公式原本同时依赖 Unity 场景查找、升级系统与 UI；结算收据规则又写在存档协调器里。修改离线规则需要理解场景及写盘顺序。本次只整理这条调用链，不修改价格、奖励公式、时间上限、等级、文件格式或切档阶段。

## 技术边界与方案审查

- 归属与复用：复用 OfflineEarnings 的公式；离线纯规则进入 Economy/Rules 独立程序集，场景升级报价读取归 OfflineUpgradeCostSource；RestaurantPersistence 保留调用时机和提交事务。
- 状态归属：钱包余额仍归 RestaurantWallet；已消费时间戳和已展示收据仍由 RestaurantPersistence 管理并写入既有存档。纯规则只接收不可变值并返回结算方案，不拥有运行时单例或持久化状态。
- 依赖方向：场景适配器/存档协调器 → 纯规则。纯规则不得反向访问场景、UI、存档 DTO、磁盘、网络或系统时钟。
- 兼容与失败：保持首次进入零收益、时间回拨、8 小时封顶、整数截断、余额饱和、未关闭收据、保存失败重试等既有语义。仍先原子保存余额/时间戳/收据，再更新内存钱包。不新增存档字段、不升版本。
- 取舍：不建立全项目服务框架，不拆解完整存档系统，不增加通用事件总线。只抽取实际有独立输入输出的结算规则及报价查询。
- 自动防线：Unity 无引擎依赖程序集 + shell 边界检查 + CI 和现有构建入口 + 纯规则/适配器/保存失败及切档回归。脚本检查依赖事实，不声称能自动评价设计质量。

## 验收

1. 离线规则程序集无 Unity/Runtime 引用，只使用显式参数计算；不读取环境时间或文件。
2. 原有精确收益样例不变；覆盖首次进入、重复结算、时钟回拨、上限、余额溢出保护和旧收据保留/替换。
3. 场景报价选择保留设施可用性、员工解锁、餐桌剩余差价及循环等级条件；纯规则不扫描 GameObject。
4. 保存失败不发钱、不消耗旧时间戳；重试只到账一次。原有 051/077/078 定向回归不因重构退化。
5. 反例检查：给纯规则加入场景/UI/文件/时钟依赖，或解除程序集限制，边界检查失败。
6. AGENTS 和 spec 模板要求开发前说明归属、状态唯一所有者、依赖方向和复用依据；不因单个重构要求所有历史文件立即迁移。
