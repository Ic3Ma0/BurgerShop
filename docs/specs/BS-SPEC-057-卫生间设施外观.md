# BS-SPEC-057：卫生间设施外观

- 版本：v1.0
- 状态：可开发
- 对应基线：GitHub `main`（应用 0.3.0 原型；卫生间玩法以 BS-SPEC-053 为准）
- 优先级与原因：用户提供卫生间参考截图，现有蓝隔间/单洗手台外观不够，需要按截图重建设施与世界芯片
- 前置依赖：BS-SPEC-053 卫生间扩建
- 用户已确认：以参考截图的卫生间家具与设施 UI 布局/体感为准；不要装入参考游戏的 Shop / Daily Reward 名称、美术或音频
- 产品建议或关键未定项：CLEAN BOT 雇佣价格与时长为本 spec 冻结的开发默认值，不是参考图精确参数

## 目标与范围

玩家目前走进已购买的卫生间，看到两间蓝色隔间、一只洗手台和 WC 字标，不像参考图里的卫生间。本次之后，已建成的卫生间应能看出三间木质厕隔、沿墙洗手台、黄色储物柜、红色 TRASH 桶、带白色交互圈的洗地机，以及英文 CLEAN BOT 倒计时芯片。

本次交付：

- 在既有 `Goal01Bootstrap` / `RestroomExpansion` 建成流程上重建卫生间家具与设施 UI
- 三间木质厕隔（含马桶），部分门半开
- 东墙洗手台
- 西墙黄色储物柜
- 红色 TRASH 垃圾桶（卫生间内，原餐厅垃圾桶逻辑不变）
- 洗地机 + 白色虚线交互圈
- 世界芯片文案 `CLEAN BOT` 与 `00m 00s` 格式倒计时（游戏内英文）
- EditMode 覆盖布局、碰撞、HUD 文案；新增碰撞体仍走现有 `link.xml` 的 Box/Capsule/Sphere 保留

本次不做：

- 不装入参考图左上 SHOP、右上 Daily Reward 的名称、图标、音频或玩法
- 不改卫生间购买价 300、解锁 Lv.4、两隔间占用、容量 4、使用 4 秒、洗手 1 秒、清洁 3 秒、等候 20 秒
- 不把第三隔间接入顾客占用或脏污存档位
- 不新增存档字段；CLEAN BOT 剩余时间不持久化
- 不改 T(n)、商城卡片经济、离线收益

## 玩家流程与规则

入口仍是 BS-SPEC-053：商店购买卫生间扩建 → 南侧固定房间开门。本次只改建成后房间内部的外观与洗地机雇佣。

| 项目 | 明确规则 |
| --- | --- |
| 触发条件 | 卫生间 `Built` 后生成家具。玩家站上洗地机白色圈并停留 0.3 秒，若 CLEAN BOT 未运行且金币足够，一次性扣费启动 |
| 费用 / 奖励 / 时长 / 上限 | CLEAN BOT：50 金币、持续 60 秒；同时只运行一段。到期后芯片回到 `00m 00s`，可再次雇佣。隔间清洁仍为每间 3 秒 |
| 状态变化 | 服务中：芯片倒数，并按既有 `Clean` 速率自动清扫已脏的两间可用隔间，不占用员工名额。未启动或到期：`00m 00s`。第三隔间仅外观，门保持半开，无脏污/占用 |
| 与已有功能的关系 | 顾客仍只使用隔间 0 和 1；玩家靠近隔间清洁、员工清洁仍有效。CLEAN BOT 与玩家/员工同时清洁同一隔间时进度叠加。金币走餐厅钱包。卫生间仍为固定建筑，不进入可摆放设施 |

## 界面与资源（涉及呈现时填写）

- 入口、显示位置、反馈时机：仅在已建成卫生间内。芯片钉在储物柜附近世界空间，面向镜头
- 正常 / 不可用 / 进行中 / 完成状态及文案：
  - 芯片标题固定 `CLEAN BOT`
  - 倒计时 `mm m ss s`（两位分钟、两位秒，如 `00m 00s`、`01m 00s`、`00m 59s`）
  - 垃圾桶正面英文 `TRASH`
  - 不可用：余额不足时不扣款、不启动，芯片保持 `00m 00s`
- 界面语言：游戏内英文；本 spec 中文
- 参考图或布局说明：面向门看向隔间时——远处三间木隔间（部分门开、可见马桶）；右侧沿墙洗手台；左侧黄色柜；近处红色 TRASH 与洗地机+白圈；柜旁 CLEAN BOT 芯片。墙/地为奶油色，隔间为木色，不用原青色隔板作为主外观
- 资源交付：沿用运行时 primitive / `RestaurantStyle` / `HudChrome` / 自绘 `FoodIcons` 占位，不引入参考游戏贴图或音效

## 边界、存档与兼容（只写相关情况）

| 情况 | 预期行为 |
| --- | --- |
| 条件不足 / 库存为空或已满 | 金币不足不能雇佣 CLEAN BOT；卫生间未建成不出现本家具 |
| 重复操作 / 多个角色同时操作 | 服务未结束再次站上白圈不重复扣费。顾客仍互斥两隔间 |
| 中途取消或离开 | 离开白圈只取消雇佣判定；已启动的 60 秒倒计时继续直到结束或离开会话 |
| 切后台与重新进入 | 不持久化 CLEAN BOT；重开为 `00m 00s`。隔间脏污仍按 v17 `restroomDirtyMask` |
| 旧存档升级到本版本 | 不升版本。已购买卫生间重开即用新外观；脏污位仍 0–3 |

不新增持久化状态。允许开发自行决定的可逆细节：隔间精确毫米尺寸、木纹深浅、洗地机零件堆叠、芯片圆角与图标像素，只要布局关系、英文文案和碰撞可测。

## 验收标准

当前优先高效实现功能：按改动做必要的本地 Unity 验证，普通逻辑优先针对性测试，视觉/交互按需通过 Computer Use 操作 Unity Play。验收保持精简，不例行要求长测、重复录像或全量回归。Android 打包与手机验收留待后期用户统一安排，不阻塞当前功能交付。

| 编号 | 初始状态 | 操作 | 必须出现的结果 |
| --- | --- | --- | --- |
| AC-01 | 卫生间已建成 | 检查房间层级 | 三间木隔间，各有马桶；至少两扇门相对关闭位明显半开 |
| AC-02 | 同上 | 检查沿墙家具 | 东侧至少两座洗手台（龙头靠墙、盆朝室内）；西侧黄色储物柜 |
| AC-03 | 同上 | 检查门侧设施 | 红色桶上有 `TRASH`；洗地机位于白色虚线交互圈内 |
| AC-04 | 同上，BOT 未启动 | 读芯片 | 文案为 `CLEAN BOT` 与 `00m 00s`；房间内无 `SHOP` / `Daily Reward` |
| AC-05 | 已建成，玩家有 ≥50 金币 | 站上白圈 0.3 秒或调用雇佣 | 扣 50；芯片为 `01m 00s` 起倒数；期间脏隔间被自动清洁 |
| AC-06 | 已建成 | 检查碰撞 | 隔板、柜、TRASH、洗手台柜、洗地机机体阻挡；白圈虚线与半开门不阻挡；`link.xml` 仍保留 Box/Capsule/Sphere |
| AC-07 | 已建成 | 寻路 | 门到两间可用隔间、隔间到洗手点仍可走；顾客仍只占用两隔间 |
| AC-08 | v16/v17 旧档 | 读档 | 购买与脏污兼容，不因本外观改动丢进度 |

输入和界面相关功能补充：本地 Unity Game View 从门侧看向隔间，确认木隔间/洗手台/黄柜/红桶/洗地机/芯片相对位置。云端无 Editor 时仍提交测试并写明未跑 Editor。

不应破坏的既有行为：卫生间购买、两隔间脏污、玩家/员工清洁、偶数号顾客如厕、商城 Restroom expansion 条、餐厅大厅垃圾桶。
