## 范围内

1. 索引损坏/缺失时发现所有占用槽（主文件或 `.bak`），编号分配核对磁盘
2. 未来版本 manifest 不降级写回
3. 创建/激活/删除/写索引返回可区分结果；内存活动槽仅在持久化成功后更新
4. `Flush` 失败则 `StartNewGame` / `SwitchToSlot` 返回 false，不切活动槽
5. `Save` 成功的快照可被同版本 `Load` 读回；超限拒绝发生在替换好档之前（读写上限 **256 KiB**）
6. 读不到档时，界面不得把「不可读 / 更高版本」显示成正常新游戏自动保存

## 技术边界与方案审查

- 归属与复用：沿用 LocalSaveStore 文件写入、SaveSlotStore 索引操作；不引入第二套存储。
- 状态归属：槽位索引归 SaveSlotStore；当前经营快照归 RestaurantPersistence，提交失败不变更活动槽。
- 依赖方向：UI 调用存档协调器，协调器调用槽位与文件存储；存储不依赖 UI。
- 兼容与失败：不升存档版本；保留未来版本与不可读文件；超限或写失败返回明确结果，不替换好档。
