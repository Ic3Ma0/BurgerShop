## 目标与范围

玩家目前只能靠绿 / 金 / 紫 / 青地面圆盘判断区域，首局不一定知道下一步该走去哪。本次之后，任何时候画面上只有**一个**当前目的地：箭头或区域高亮，外加一句英文 HUD，指向现有循环中的下一处。

希望解决：第一次进店时「烤台好了不知道去绿点、手里有汉堡不知道去金点、攒够钱不知道去紫点或青点」。

本次交付：

- 按下方优先级，根据**当场经营状态**推导下一步，不写 `tutorialCompleted` 之类新存档字段。
- 对当前目标区给出可见指引：地面箭头、区域高亮、一句英文 HUD，至少同时具备「指向目标区」和「英文短句」两种；允许三者都做。
- 覆盖现有循环：烤台有货 → 绿色取餐 → 金色交付 → 余额够时紫色升级 → 余额够时青色雇佣。雇到人之后只显示短暂的 “Staff is delivering”，不增加第二间店或第二种商品。
- 竖屏可玩；新 HUD 不得挡住左下摇杆，不得改 `VirtualJoystick` / `SafeAreaFitter`。
- 指引不锁移动、不弹强制教程、不截获摇杆触控。

本次不做：

- 不改单价 10、烤台升级 30/60、雇佣 50、出餐时间、库存 / 携带上限、顾客规则。
- 不新增存档字段，不升 `RestaurantSaveData` 版本，不引入离线收益。
- 不把 UI 改成中文；不引入 Pizza Ready 名称、截图、模型或 UI。
- 不改摇杆位置、尺寸、触控；不改 SafeArea 计算。
- 不做会暂停、遮挡全屏或必须点掉才能走路的新手关。
- 不把雇人之后的「再升一级烤台 / 完成 N 单」做成新目标（那是 011）。

## 玩家流程与规则

入口：`SampleScene` Play 后由现有运行时组装店铺。指引在玩家可移动后立即根据当场状态出现，无需额外操作开启。

| 项目 | 明确规则 |
| --- | --- |
| 触发条件 | 会话开始后持续根据当场状态刷新。任一时刻只显示一个下一步。玩家走到目标区后，箭头可收起或减弱，英文句保留为「正在做这件事」。 |
| 费用 / 奖励 / 时长 / 上限 | 不收费、无奖励、无时长关卡。升级 / 雇佣是否「买得起」只**读取**当前价目与钱包，不改数字。 |
| 状态变化 | 指引是会话内显示状态，随携带、烤台库存、队首是否就绪、余额、烤台是否满级、是否已雇人变化。重开后按恢复后的长期进度 + 当局重建的临时状态重新计算。 |
| 与已有功能的关系 | 与玩家共享烤台库存、收银点、钱包。员工仍按 0.1.2 自动取餐送餐。本刀不改变这些规则，只指出玩家该走去哪。 |

### 下一步优先级（从高到低，写死）

同一时刻只取第一条命中的规则。`可立即取餐` = 玩家空手 **且** 烤台库存 ≥ 1。`可立即交付` = 玩家携带 ≥ 1 **且** 队首已就绪（走到排队位并完成点单）。`买得起升级` = 未雇人 **且** 烤台未满级 **且** 金币 ≥ 当前下一级价格。`买得起雇佣` = 未雇人 **且** 金币 ≥ 当前雇佣价。

1. **交付（金）**：可立即交付 → 指向金色交付点。即使同时也买得起升级 / 雇佣，仍先送餐。
2. **取餐（绿）**：可立即取餐 → 指向绿色取餐点。即使同时也买得起升级 / 雇佣，仍先取餐。
3. **手满或仍拿着汉堡、队首未就绪**：指向金色交付点，文案改为等待顾客。不把玩家送去升级 / 雇佣，避免端着汉堡离开收银点。
4. **升级（紫）**：买得起升级，且当前不是 1–3 → 指向紫色升级区。
5. **雇佣（青）**：买得起雇佣，且当前不是 1–4 → 指向青色雇佣区。紫与青不同时抢：两者都买得起时只指紫色。
6. **已雇佣**：玩家空手 → 指向员工或保持无地面箭头，英文为员工正在送餐。玩家若仍拿着汉堡，继续走规则 1 或 3，把手里的汉堡送完。已雇佣后不再把紫色升级当成「下一步」（留给 011）。
7. **兜底（未雇人、空手、烤台还在做、钱不够升级也不够雇）**：指向绿色取餐点，文案为在绿点等出餐。

新开局（0 金币、烤台 LV1、未雇人、空手、库存随当局重建）走规则 7，烤台出第一份后改走规则 2。老存档若已有金币 / 已升级 / 已雇人，跳过已经完成的步骤，直接显示**当前**下一步，不重放首局序列。

## 界面与资源（涉及呈现时填写）

- 入口、显示位置、反馈时机：世界空间指向当前目标区（箭头和 / 或该圆盘高亮）；英文短句放在现有顶部状态条一带（可替换现有 “Drag joystick to move”，或紧挨其下新增一行）。新 UI 必须挂在现有 `SafeArea` 子节点下，从而沿用已有安全区，而不是改 `SafeAreaFitter`。
- 正常 / 不可用 / 进行中 / 完成状态及文案（界面语言：英文）：

| 规则 | HUD 文案（必须英文，可微调用词但语义不变） |
| --- | --- |
| 1 交付 | `Serve: GOLD spot` |
| 2 取餐 | `Pickup: GREEN spot` |
| 3 拿着汉堡等顾客 | `Wait at GOLD — customer coming` |
| 4 升级 | `Upgrade grill: PURPLE spot` |
| 5 雇佣 | `Hire staff: CYAN spot` |
| 6 已雇且空手 | `Staff is delivering` |
| 7 等出餐 | `Wait on GREEN — grill cooking` |
| 已站在当前目标区内 | 保持同一语义，可改成进行中：`Picking up` / `Serving` / `Stay to upgrade` / `Stay to hire`；地面箭头收起或明显减弱 |

- 参考图或布局说明：竖屏 1080×1920 参考。左下虚拟摇杆现为锚点 `(0,0)`、位置 `(220, 240)`、尺寸 `280×280`，新 HUD **不得进入该矩形及其外侧约 24px 边距**。顶部已有金币、携带、顾客、员工状态；新短句不要盖住右上 `COINS`。底部中央存档条、右下仅在站上区域才出现的升级 / 雇佣面板保持现有逻辑。`raycastTarget` 必须为 false。
- 资源交付：沿用现有占位几何体与内置字体即可，不需要最终美术，禁止贴 Pizza Ready 素材。

## 边界、存档与兼容（只写相关情况）

| 情况 | 预期行为 |
| --- | --- |
| 空手、烤台无货 | 未雇人且买不起升级 / 雇佣 → 规则 7 等绿点；买得起则走 4 或 5。 |
| 手满（携带已达上限） | 有就绪队首 → 规则 1 去金点；否则规则 3 在金点等。不指向绿点。 |
| 队首未就绪 | 手里有汉堡 → 规则 3；空手则按 2/4/5/6/7，不出现交付箭头。 |
| 金币不够升级 / 雇佣 | 不指向紫 / 青。继续走取餐、交付或等待。 |
| 已雇佣 | 空手 → 规则 6「Staff is delivering」。不再指向青点，也不在本刀把紫点升级当成下一目标。 |
| 重复操作 / 玩家与员工抢同一库存 | 指引只看**玩家**携带与当场库存 / 队首；员工照常工作。不新增节流，不让玩家跳过收银冷却。 |
| 中途离开目标区 | 若该步仍是最高优先级，箭头与文案恢复指向该区；不扣费、不锁人。 |
| 切后台与重新进入 | 不保存指引本身。回来后按当场状态重算。 |
| 旧存档升级到本版本 | **不新增持久化状态。** 用已有金币、烤台等级、是否已雇人，加上当局重建的位置 / 携带 / 烤台库存 / 顾客队列推导。禁止为了「教程做完了」增加存档字段。 |

允许开发自行决定的可逆细节：箭头是 3D mesh、世界空间 UI 还是目标圆盘脉冲高亮（或组合）；箭头高度与脉冲速度；新短句是改现有 MoveHint 还是另起一行；已站在目标区时箭头是隐藏还是缩小。不可逆或会挡操作的选择（全屏遮罩、改摇杆、改 SafeArea、新存档字段）不允许。

## 验收标准

每条均可在 Editor `SampleScene` Play 中观察。涉及手机输入的条目在 vivo S50 竖屏上确认，**本草案不宣称真机已通过**。

| 编号 | 初始状态 | 操作 | 必须出现的结果 |
| --- | --- | --- | --- |
| AC-01 空手取餐 | 新开局或等效：未雇人、空手、烤台库存 ≥ 1、玩家不在绿点上 | 站在店内非取餐区观看 | 指引指向绿色取餐区（箭头和 / 或高亮）+ 英文取餐句。不出现升级 / 雇佣指引。 |
| AC-02 携带去交付 | 玩家携带 ≥ 1、队首已就绪、不在金点上 | 不走进交付点，先观察 | 指引改为金色交付区，取餐指引消失。文案为 Serve / GOLD。 |
| AC-03 手满 | 玩家携带已满、烤台仍有库存 | 观察 | 仍指向金点（有客则交付，无客则等待），不指向绿点让玩家继续取。 |
| AC-04 无就绪顾客 | 玩家携带 ≥ 1、队列里没有已点单的队首 | 观察 | 指向金点 + 等待顾客文案。不指向紫 / 青。 |
| AC-05 钱不够 | 未雇人、烤台 LV1、金币 < 当前升级价且 < 雇佣价、空手、烤台正在做（库存 0） | 观察 | 指向绿点等出餐。不出现紫 / 青为「下一步」。 |
| AC-06 可升级 | 未雇人、烤台未满级、金币 ≥ 当前升级价、空手、烤台库存 0（不能立即取餐）、不能立即交付 | 观察 | 指向紫色升级区。即使同时也买得起雇佣，仍只指紫色。 |
| AC-07 可雇佣 | 未雇人、金币 ≥ 雇佣价、不满足 AC-06（例如烤台已满级，或余额够雇但不够下一级升级）、空手且不能立即取餐 / 交付 | 观察 | 指向青色雇佣区。不与紫色同时作为下一步。 |
| AC-08 已雇员工 | 已雇佣、玩家空手 | 观察员工自动取餐或送餐 | 英文为 `Staff is delivering`（或语义相同）。不出现「去开第二间店」，不把雇佣区再当成下一步。 |
| AC-09 老进度跳步 | 读入已有金币 / 已升级或已雇人的 0.1.2 存档后进入 Play（库存与携带按现有规则重建） | 不清除存档、不添加教程标记 | 指引直接等于当前优先级结果，不从「第一次等出餐」重放。存档字段与版本不变。 |
| AC-10 不挡操作 | 竖屏 Play，摇杆与顶部 HUD 可见 | 用 WASD 或摇杆从绿点走到金点完成一次交付 | 移动全程可用。新 UI 不截获点击。指引不挡住摇杆盘，也不挡住右上金币。 |
| AC-11 Editor 场景 | Unity Editor 打开 `Assets/Scenes/SampleScene.unity` 进入 Play | 走 AC-01→AC-02 一次手动循环 | 店铺仍由运行时组装；无需在场景里手摆指引预制件也能看到下一步。 |

手机相关：用户回复 010 并完成实现后，在 **vivo S50 竖屏** 安装当前包，用**单指摇杆**完成一次取餐 → 交付。必须确认指引可见、不盖住摇杆与顶部金币 / 员工 HUD，logcat 无新的游戏异常。横屏不是本刀通过条件，但若可切换，新 HUD 仍不得挡住摇杆。**成功打出 APK ≠ 真机通过；在设备确认前不得把本 spec 标成已验收。**

不应破坏的既有行为：出餐、取餐、交付 10 金币、升级停留 1.5 秒与 30/60、雇佣停留 1.5 秒与 50、玩家与员工共享库存 / 收银冷却 / 钱包、现有存档五字段、摇杆与 SafeArea 行为。

验证建议（开发侧，不代替验收表）：针对优先级规则做 EditMode 测试，用当场状态推导下一步，**不得**读写真实 `persistentDataPath`。玩家可见循环以 SampleScene Play 为准。
