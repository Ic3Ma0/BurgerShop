# BS-SPEC-083：经济一致性修复与 0–15 级节奏标定

- 版本：v1.0，2026-09-22。
- 状态：可开发；本文件只交付产品规则，尚未实现或完成节奏验收。
- 基线：当前工作区 080/081 实现；与 082 人物外观并行，保留其他 Agent 改动。
- 优先级：先处理花钱无效、错误引导和奖励参考异常，再调整有测量依据的价格。
- 用户已确认：检查设施购买/升级、雇员/员工升级、玩家升级、扩建的整体经济；不合理处修订；继续聚焦 0–15 级、本地 Unity。
- 产品建议：以下局部修复和测量驱动的定价方式；数值目标是本次产品设计标准，不是已验证的玩家心理定律。
- 依据：[本轮经济审计](../design/ECONOMY_REVIEW_2026-09-22.md)、[内核](../GAME_CORE.md)、[080](BS-SPEC-080-首单晋级与经营成长修订.md)、[081](BS-SPEC-081-小店开局与首轮扩建.md)。

## 1. 目标和范围

让玩家花钱能得到可解释的改善，买之前知道完整费用，经营中有接近且有意义的下一个目标。经济调整服务既有生产、搬运、销售和扩店，不添加新货币、租金、原料费、工资、广告或新玩法来强行消耗金币。

本次分两段交付：A 修明确问题；B 以 A 后的稳定版本测量 0–15 关键阶段并进行必要局部调参。A 完成只能称经济一致性修复完成；没有 B 的实测不能宣称 0–15 经济已平衡。Lv.16+ 与整体离线产出公式列为后续独立项，不混入本轮价格改造。

## 2. 固定规则与真实报价

1. 保留首单 2 星晋级、Lv.2 起星星单门槛、有效投资 +2 星、080 删除无意义固定属性任务。不要新增“每单发经验”或提高星奖励来遮盖消费问题。
2. 初始机教学升级 30/60、三名员工雇用 50/100/200、主厅 150、餐桌样式 50/80/120、属性 50×1.18^n 与重复设施 1.25^持有数先作为基线。B 有证据才改具体项目，不统一涨价或降收入。
3. 同一设施同一状态，商城、详情、引导和结算必须读同一个真实报价。区分基础价、当前完整价、已付金额和剩余应付；显示值与扣款一致。按交易前持有数定价，确认时若报价已变化先刷新，不能静默多扣。
4. 显示可乐、蓝盒汽车、纸袋等完整营业所需的缺失项。已有设施、免费开放项、已买地不重复计费；利用自有空间营业与购买侧翼分别说明。不要强迫玩家购买原本可选的侧翼、卫生间或第二柜台。
5. 首个车窗 Lv.6、骑手首套 Lv.8、专用自动化 Lv.9 保持现有免费开放语义。免费开放和迁移不额外授予付费建设星。
6. 首雇主厅前置在 UI、购买条件和实际可达区域中一致；允许分段存入主厅的款项，但建设前旧店必须持续可营业。

## 3. A：确定性修复

### A1. 汽车窗口升级产生真实收益

当前额外购买的 CarCounter 能付 100/200 升级，却没有改变 DriveThruLane 的固定冷却。

- 保留两档费用 100、200 与每档 +2 星。
- 将该窗口相邻两次开始交付的最短冷却设置为 L1 0.75 秒、L2 0.65 秒、L3 0.55 秒。0.42 秒交付动画、单价、订单数量和车流保持原规则。
- 冷却在开始一次交付时计时，与交付动画重叠，不能再串行叠加一次。由同一窗口所有操作者共享，不按玩家/员工人数倍增出餐。
- 详情显示 `Service interval 0.75s → 0.65s` 等实际参数；不宣称整店收入必增对应百分比。
- 原始/商城窗口如提供升级，使用同一能力规则。没有升级入口的窗口不为此新加收费项目。
- 已购买的等级重载后立即生效，不再扣费、补星或要求重买。

### A2. 投资建议解释实际价值

- 不能只根据最低价选择主推荐。保留同时一个稳定目标，以及主动查看其他投资的能力。
- 前置优先：首单/清理教学、合法营业缺件和首次雇员按真实状态提示；金币/星星已足够时仍可直接晋级，不被推荐锁住。
- 从当前已有状态识别持续瓶颈：生产跟不上且下游缺货→生产；机上有货但运输不足→搬运/员工；货足且柜台持续有队列→服务；用餐位置持续不够且可清桌问题已排除→座位。一次偶发空库存不触发反复换目标；默认持续观察 10 秒，可用现有状态和会话内计时，不建立永久分析系统。
- 没有明确瓶颈时可推荐低成本的有效改善，但必须说明真实参数/外观/减少操作的价值，不把“+2 星”当唯一购买理由。
- 不把同一种设备“更快生产”承诺成必然增收；下游明显堵塞时不优先推荐继续堆同一环节。
- 员工数为 0 时，员工属性购买入口提示 `Hire staff first`，不扣费、不发星；已有旧档员工属性照常保留，首次雇用后生效。UI、推荐和实际购买入口条件一致。
- 玩家可以自由购买其他合法投资，不因系统推荐而锁定购买路线。存在可行其他目标时提供可见替代入口；没有可行项时作为开发错误处理，不提示“继续卖就会长星”。

### A3. 离线参考价不因尾款异常缩水

- 参考仍来自当前已开放且有效的升级，保留 051/079 的员工系数、8 小时上限和一次性结算；本段不冒充“已经按实际产出结算”。
- 对同一个尚未完成的桌椅升级，离线估值使用候选样式完整标价，不用扣除投资后的尾款。当前仍可选的最低完整标价为 50；剩余付款若为 1，不能用 1 当生产价值。
- 如档位全额已付、只差确认样式，仍按该合法候选的完整标价估值；确认与否不应造成 1→几百的突变。确认完成后正常从未完成候选中移除。
- 无雇员时依旧无离线经营收益；员工升级报价仅在已雇员时参与有效候选。无有效候选返回既有安全结果 0，不虚构无限奖励。
- 报价适配器只提供参考，不能更改玩家实际尾款或再发钱。补丁前已结算的收据不追溯重算或补发，保护存档与切槽幂等。
- 修复后仍明确记录：该公式是升级等价奖励，尚未验证“与实际经营收入成比例”和“一晚相当于 6–10 次升级”。完整公式改造另立规格，不能把这个局部修复报成回访经济已验收。

## 4. B：标定方法与允许的调参

### 4.1 用实收金币计算，不用理论产能代替

```text
R（金币/分钟）= 窗口内正常经营入账 / 窗口有效经营分钟
T_next（秒）= 60 × max(0, C_due - Wallet) / R
T_open（秒）= 60 × max(0, Sum(必要剩余投入) - Wallet) / R
ROI（分钟）= 单笔投入 / (R_after - R_before)，仅当增收为正
```

记录窗口开始/结束的钱包、地面现金、经营入账、支出、当前设备/员工/等级。收入不能直接用钱包差算，因为中途购买会降低钱包；收取窗口开始前地面存款不是窗口内新产出。暂停/菜单时间单列。操作简化、减少往返和外观价值另记，不强行换算成收益。

比较前后时固定客流随机种子、设备与路线，稳定测量窗口建议 180 秒。完整多段自然试玩可直接提供覆盖窗口，已有足够数据不重复跑；短教学按实际事件计时。自动安排资金/跳级的夹具只能证明局部行为，不能作为自然从新档攒钱时长。

### 4.2 覆盖的关键状态

| 状态 | 要回答的问题 |
| --- | --- |
| 新档首单、Lv.2 清桌与 30 金币升级 | 能否无需额外消费完成首单；拿到 2 星后知道差额与赚钱路线 |
| Lv.3 主厅+首雇 | 从当前钱包到 200 完整投入需多久；雇人后收益或操作负担有何改善 |
| Lv.4–6 第二机器、可选柜台、蓝盒与汽车 | 哪个是真瓶颈；是否错误推荐未能售卖的半条产线；首窗是否被重复计费 |
| Lv.7 可乐 | 利用自有空间的 450 路径与侧翼 750 路径分别估值；开业后旧店是否因调度下降 |
| Lv.8→9 自动化前后 | 实际整店 R、骑手贡献、必要操作量；是否出现所有近期目标瞬间买完 |
| Lv.10 纸袋及 Lv.12/Lv.15 | 完整 750 投入与现有业务收益；晚期是否只有无效属性凑星；下一目标是否可见 |
| 同阶段偏好不同的购买路线 | 至少核对生产/雇员路线与玩家/家具路线；不要求穷举每种购买排列 |

保留一条自然新档至 Lv.15 的事件记录用于衔接，不要求每修一个局部问题重跑全程。用代表存档回归受影响区间。测试隔离真实存档，仅本地 Unity。

### 4.3 标定标准

沿用内核的阶段时间窗作为目标，而非把等级硬等同于分钟：

- 首 0–5 分钟：下一项小目标预计 3–15 秒；教学首次购买实际超过该带时先排查收钱与引导，不先涨收入。
- 5–20 分钟：下一项小投资预计 15–60 秒。
- 20 分钟后：可存在 1–5 分钟的大扩建/业务目标；同时必须有当前可推进、能改善经营的小目标或可选加速经营路径。连续超过 90 秒只能重复原操作、没有有价值选择，即节奏失败；部分付款本身不算改善。
- 已经攒够钱的小目标 T=0 是正常奖励，不能据此涨价。仅当自然经营连续跨过三个本应承担成长选择的投资节点、没有体会收益，就应复核是否过快；不采用“钱包太多就涨价”。
- 只因玩家购买非推荐项、装饰偏好或主动停下而变慢，不算系统卡死。必须保留基础赚钱路径和有意义的可选目标。
- 90 秒判据关注当前有无真实经营选择，不能靠新增无收益杂务、强制点击或广告门槛伪造出口。

### 4.4 调整顺序和数值交付

1. 先修程序/解释/动线问题、无效属性、完整报价，取得 A 后基线。
2. 参数真实生效但未解除瓶颈，改推荐或局部能力，不先调所有售价。
3. 当某阶段没有处于目标时间带的有用投资，才调整该项费用或收益。选该阶段固定配置，以实际基线 R 与目标时间核算：`成本候选 = ceil10(R_baseline × 目标秒数 / 60)`。它适用于从零预算的代表性目标；有当前余额与阶段内产能变化时用完整事件记录复核，不直接套一次余额。
4. 每次只改一个相关参数组。列出旧价/新价、收益前后、适用阶段、调前/调后 T 和使用的收入数据。若已符合时间带，不为凑公式修改。
5. 对设施重复价格核对低持有数及实际合理布局的较高持有数；对员工升级核对 1 人与 3 人。便宜升级可以存在，价格曲线不要求每条轨道同形。
6. 不在运行时根据玩家当前金币、最近赚得快慢或接近目标程度动态涨价；永久价格只有显式经济配置版本。主厅、初始升级、雇用、属性曲线、侧翼、纸袋等只改测出问题的项。售卖单价、等级加成和星阈值暂保留；若证据表明必须改这些跨系统杠杆，另写明确后续修订，避免一批同时变化无法解释。
7. 自动化保留释放操作负担的价值。先检查后续目标组织和报价，不为延时随意削减产出或添加工资。

## 5. 边界与兼容

- 钱包不允许负数；钱不足、非法前置、重复确认、取消摆放、移动已有设备均不重复扣款或发星。生产与销售遵守共享库存和订单一次结算。
- 已买设施/土地/员工/属性/星星和已结算收据完整保留，不为了新版平衡收回奖励、补收差价或降低已拥有等级。
- 若 B 调整价格：只影响未来购买。已部分投入的未完工项目不增加原来剩余应付；新剩余取旧承诺剩余与新价扣已付后的较小值，下限 0。需要旧报价信息时由开发明确持久化方案和迁移，不能从新价格反推历史付款。降价后完成只结算一次原建设奖励，不再现金退款造出套利。
- 旧档中未雇员却已有员工属性的状态合法保留，不回退；新购买执行已雇员条件。
- 离线一次入账继续遵守 079 的先保存后发布；失败重试、切槽、重复打开面板不得再次发钱。

## 技术边界与方案审查

- 归属与复用：价格由现有目录/升级规则拥有；补足调用一致性，不全仓重写。汽车冷却由窗口服务系统消费对应等级；投资指引只读状态和报价，不扣款或生成另一套经济规则。
- 状态归属：钱包唯一为 RestaurantWallet；星/店铺等级为 SessionGoalTracker；设施/员工等级各由已有所有者维护；短观察计时归引导会话。B 的测量优先复用测试日志，不新增云分析或永久玩家画像。
- 依赖方向：规则提供参数→实际经营使用→UI 展示；离线报价适配器→既有纯规则→保存协调器，保持 079 的规则层不读取场景与系统时间。
- 兼容与失败：重复确认、余额不足、旧档、部分付款、离线保存失败分别用原事务/存档边界处理；实现前补充具体变更所有者、必要 schema 版本与迁移说明。
- 自动防线：共享冷却、价格/扣款一致、无人不能购买员工属性、尾款不改变离线参考价值、关键星源可达和相关存档测试；运行 `bash scripts/check-boundaries.sh --spec docs/specs/BS-SPEC-083-经济一致性修复与节奏标定.md`。不因本次发现扩大为无关架构改造。

### 开发方案补充（2026-09-22）

- 归属与复用：DriveThruLane 持有单窗口服务等级，复用设施已有等级快照与 GrowthUpgrades；FacilityLayout 汇总目录价与原建设抵扣，各 UI 读取同一报价。
- 状态归属：推荐纯规则只持有会话观察计时；场景适配器只读机器、库存、队列与座位。营业缺件报价是既有价格汇总，不产生新的购买状态。
- 依赖方向：场景观察与报价 → 推荐纯规则 → 既有胶囊；出餐间隔函数同时提供实际能力和详情文案。
- 兼容与失败：本轮不改价格或存档 schema；窗口复用 custom 等级字段。零员工旧属性保留，仅阻止新购买。摆放报价变化先提示刷新，重复提交不得扣款；旧离线收据不重算。
- 自动防线：定向 EditMode 验证实际窗口交付、共享冷却、重载、无人升级、隐藏桌及全付未选择的报价、营业缺件、推荐观察和交易；离线 051/079 与存档回归。B 记录区分自然经营、测试夹具与待测阶段。
